# Workflow

사용자가 요청한 결과와 실행 범위를 확인한다. 이전 작업을 이어 달라는 요청은 대화에서 합의한 범위에 맞춘다. 실행 권한은 [스킬 실행 원칙](../../../AGENTS.md#스킬-실행-원칙)을 따른다.

명확한 구현, 진단, 리뷰는 해당 스킬에서 바로 시작한다. 구현 중 관련 테스트와 자체 검토가 필요하면 구현 절차 안에서 이어서 수행한다.

## 절차 선택

| 요청 | 읽을 절차 |
|---|---|
| 결함을 수정한다. 합의된 API 동작으로 복구하는 경우도 포함한다. | [버그 수정](<references/버그 수정.md>) |
| 응답, 입력, 인증, 오류 또는 정렬 등 공개 API 계약을 바꾼다. | [API 계약 변경](<references/API 계약 변경.md>) |
| 코드 리뷰만 요청한다. 리뷰와 기존 CI 결과 조회를 함께 요청한 경우도 포함한다. | [읽기 전용 리뷰](<references/읽기 전용 리뷰.md>) |

요청에 맞는 절차를 읽고 필요한 스킬을 그때 참조한다. 결과가 서로 독립적이면 요청한 작업을 각각 처리한다. 버그를 고치려면 공개 계약을 바꿔야 한다는 사실을 발견하면 그 결정에 의존하는 변경을 보류한다.

그 밖의 요청은 필요한 스킬에서 바로 시작한다. 요구사항 정리는 [define](../define/SKILL.md), 계획은 [plan](../plan/SKILL.md), 기능 구현은 [implement](../implement/SKILL.md), 테스트 작성은 [test](../test/SKILL.md), 검사 실행이나 결과 확인은 [verify](../verify/SKILL.md), 원인 조사는 [debug](../debug/SKILL.md)를 따른다. 사용자가 리뷰와 수정을 함께 요청하면 [self-review](../self-review/SKILL.md)의 수정 범위를 따른다.

## 완료 기준

작업을 시작할 때 검증할 결과와 사용할 근거를 정한다. 마무리할 때 실제 확인한 결과를 근거와 연결한다. 확인하지 못한 항목은 이유와 함께 기록한다.
