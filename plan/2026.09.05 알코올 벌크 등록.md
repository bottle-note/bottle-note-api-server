# 알코올 벌크 등록

## Overview

사용자가 승인한 기존 검증 개선을 구현하고 두 가지 경로를 제공한다: Excel 템플릿 생성 → 검증 → 벌크 저장, JSON 구조 데이터 → 검증 → 같은 벌크 저장. Excel 형식에 저장 서비스가 종속되지 않는다. 데이터 중복/카테고리 불일치의 정리는 사용자가 추후 수행하며 자동 병합하지 않는다.

### Assumptions

- Admin 인증 정책 안에서 현재 API 저장소를 수정한다. 외부 Admin Dashboard 신규 화면은 이번 API 작업 범위가 아니다.
- 최대 1,000행을 동기 처리하며 전체 사전 검증 후 하나의 트랜잭션으로 저장한다. 오류가 있으면 0건 저장한다.
- 이름/유효 enum/저장 가능한 값/참조 ID는 검증하고 중복 후보·새 category·type/category의 의미상 불일치는 경고로 반환한다. 기존 DB 데이터는 변경하지 않는다.
- age/cask/description/image는 선택이다. 도수/용량은 숫자와 명시 단위를 정규화한다. 범위/배치/세트 표현은 원문을 보존하고 경고한다. 명백한 숫자 범위 오류·단위 오류는 거절한다.
- 새로운 스키마·category 테이블·자동 병합·import session·멱등성 저장소·이미지 bytes 업로드는 추가하지 않는다. 반복 POST는 새 등록 요청이다. 이미지는 기존 업로드 viewUrl을 선택으로 전달한다.
- 저장 시 검증 결과의 valid 플래그를 신뢰하지 않고 전체 값을 재검증한다.

### Success Criteria

1. 실제 내려받은 Excel을 채워 validate한 normalized 행을 JSON bulk에 보내면 DB와 태그 매핑에 저장된다.
2. Excel 없이 동일 JSON을 validate한 뒤 bulk에 보내도 동일 결과를 얻는다.
3. optional 필드·단위·한글/영문 enum·그룹 자동 도출·중복 경고가 두 경로에서 일관된다.
4. 잘못된 enum/참조/도수/길이, 수식/외부 링크/크기 및 행 한도는 안정적인 오류를 반환하며 invalid bulk는 전혀 저장하지 않는다.
5. 생성 ID를 clientRowId와 대응시켜 반환하며 이미지 이벤트와 감사 기록을 보존한다.
6. GitHub Actions ci_pipeline의 unit/rule/product+admin integration/build가 최종 커밋에서 통과한다.

### Impact Scope

mono alcohol DTO/service, admin Excel/controller/OpenAPI/config, 해당 unit/HTTP/OpenAPI tests. 기존 공유 Repository 포트를 재사용하며 필요한 집합 조회만 추가할 수 있다. JPA entity와 migration은 변경하지 않는다.

## Execution Mode

- mode: delegated
- scope: plan, implement, test, self-review, commit, push, verify (GitHub Actions)
- authorization: 앞선 수정안에 대한 진행 승인과 2026.09.05 사용자 요청의 두 end-to-end 경로 및 orchestration/GitHub Actions 검증 지시를 반영한다.
- verification: 로컬에서는 컴파일·포맷 등 개발 피드백을 사용하고 최종 전체 검증은 작업 브랜치 workflow_dispatch로 수행한다. 사용자 지시에 따라 local full verify → push 순서는 push → Actions full verify로 대체한다.
- excluded: merge, release, deploy, 운영/개발 DB 쓰기, 외부 Dashboard 수정, PR 생성
- stop-conditions: 가정 붕괴, verify 3회 반복 실패, scope 밖의 되돌리기 어려운 행동

## Public Contract

- `GET /admin/api/v1/alcohols/excel/template`: 기존 템플릿 생성.
- `POST /admin/api/v1/alcohols/excel/validate`: 기존 응답을 유지하고 각 행에 `normalized` 공통 JSON 입력과 `clientRowId`를 추가한다.
- `POST /admin/api/v1/alcohols/bulk/validate`: `{rows:[AdminAlcoholBulkRowRequest]}`. 상태 변경 없이 행별 normalized/errors/warnings/candidateAlcoholIds와 집계 반환.
- `POST /admin/api/v1/alcohols/bulk`: 같은 body를 재검증 후 전체 저장. 성공 200 data.createdRows 및 data.rows(clientRowId,alcoholId), data.validation. invalid는 400 success=false errors에 검증 결과.
- clientRowId는 호출자 지정 식별자이고 요청 내 유일해야 한다. Excel은 원본 행 번호를 문자열로 사용한다. 수정/정렬 후에도 반환 normalized를 그대로 전달한다.
- row fields: clientRowId, korName, engName, abv, type(String), korCategory, engCategory, categoryGroup(String), regionId(Long), distilleryId(Long), age, cask, description, volume, tastingTagIds(List<Long>), imageUrl.
- normalized도 같은 row type이며 canonical enum names 및 %/ml 표기를 사용한다. type을 문자열로 받아 기존 AlcoholType의 unknown→WHISKY fallback을 거치지 않는다.
- errors가 없는 행만 normalized를 반환한다. 파일 내부/DB 중복, 중복 태그 제거, 비표준 범위/세트 표기, 기존 참조에 없는 category는 warning이며 저장 가능하다.
- 실제 category enum 자체가 잘못되거나 한글/영문 category가 비어 있으면 오류다. group 생략 시 정확히 하나인 category reference로 도출하고, non-WHISKY는 OTHER 기본값을 허용한다. 추론할 수 없는 WHISKY group은 오류다.
- Excel은 데이터 시트/헤더를 검사하되 안내문 텍스트·보조 시트 순서·추가 메모 시트는 허용한다. 첫 2행 구조를 유지하며 수식/외부 링크·미지원 데이터 열은 거절한다.

## 입력 상세

| 입력 항목 | 적용 규칙 |
| --- | --- |
| rows | 1~1,000행이며 null 행은 거절한다. |
| clientRowId | 필수 문자열, 공백 정리 후 요청 내 유일하며 최대 255자다. |
| korName, engName | 각각 필수, 앞뒤 공백 정리 후 최대 255자다. |
| abv | 필수, 단일 값은 0~100이며 %로 정규화한다. 40, 40.00, 40%는 40%다. |
| volume | 필수 양수이며 ml로 정규화한다. 700, 700ml, 70cl, 0.7L는 700ml다. |
| type | WHISKY, RUM, VODKA, GIN, TEQUILA, BRANDY, BEER, WINE, ETC 또는 각 한글 표시값이다. 영문 대소문자와 앞뒤 공백을 정리한다. |
| korCategory, engCategory | 각각 필수, 최대 255자다. 새로운 조합과 기존 참조와의 의미상 불일치는 경고한다. |
| categoryGroup | SINGLE_MALT, BLEND, BLENDED_MALT, BOURBON, RYE, OTHER 또는 각 한글 표시값이다. 생략 시 위 계약에 따라 추론한다. |
| regionId, distilleryId | 각각 필수, 실제 존재하는 양수 Long ID다. JSON의 소수를 정수로 잘라서 사용하지 않는다. |
| age, cask | 선택, 공백은 null이며 최대 255자다. 임의의 대체 문자를 강제하지 않는다. |
| description | 선택, 공백은 null이며 MySQL TEXT에 맞춰 UTF-8 65,535바이트 이하다. |
| tastingTagIds | 선택, 최대 1,000개이며 존재하는 양수 Long ID만 허용한다. 중복 ID는 경고 후 한 번만 저장한다. |
| imageUrl | 선택, 최대 255자의 http/https URL이다. 기존 업로드 완료 후 받은 viewUrl을 사용한다. blob URL, 인증정보 포함 URL, 서명된 임시 업로드 URL은 거절한다. |

도수/용량의 범위·배치·세트·주석은 해석 가능한 형태에 한해 원문을 보존하고 경고한다. 예를 들어 40~46%, 700ml x 2, batch A: 40% / batch B: 43%, 약60(배치마다상이)%, 1L(1000ml)을 허용한다. 숫자의 소수 자릿수를 임의로 반올림하지 않으며 101%, 0ml, 4,0 같은 잘못된 값은 거절한다.

중복 후보는 한글 이름+증류소+도수+용량으로 판정한다. 이름은 Unicode NFKC와 공백·대소문자를 정리하고 수량 단위를 통일한다. 타입과 카테고리는 후보에서 제외하므로 잘못 분류된 기존 데이터도 나중에 사람이 비교할 수 있다. 후보 ID는 정렬해서 최대 100개를 반환하며 자동 병합·덮어쓰기는 하지 않는다.

엑셀은 기존 오류 코드와 한글 필드명을 유지하며 공통 검증 결과를 변환한다. JSON은 필드 이름과 공통 오류 코드를 반환한다. 엑셀 응답의 각 rows[].normalized를 모아 JSON의 rows로 보내며, 이미지가 필요하면 업로드 완료한 imageUrl을 해당 행에 추가한다.
