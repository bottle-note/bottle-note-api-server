# Plan: 기존 알림함 발생처 확장

Status: In Progress

## Overview

bottle-note/workspace#383의 발생처 확장과 #373의 댓글·좋아요 활동 이벤트 공동화를 구현한다. 기존 notifications 테이블에 댓글·대댓글·좋아요·팔로우 알림을 저장하며 기존 문의 답변 동작을 유지한다.

## Scope

- 대댓글은 리뷰 작성자와 직접 부모 댓글 작성자에게 알린다. 행위자는 제외하고 동일 수신자는 답글 알림 한 건으로 합친다.
- 좋아요·팔로우는 활성 상태 전이에만 알림 대상이 된다. 반복·취소에는 생성하지 않고 재활성화해도 동일 관계의 최초 알림 한 건을 유지한다.
- 댓글·좋아요는 단일 활동 이벤트를 발행하고 History와 Notification이 각각 처리한다. History의 기존 기록 조건과 본문을 유지한다.
- 원본 rollback에는 부수효과를 만들지 않는다. 수신자별 알림 저장을 독립 트랜잭션으로 처리하고 기존 DB 고유 키로 동시 중복을 제거한다.
- 기존 목록·필터·HMAC cursor·미읽음·최초 읽음 계약을 유지한다. OPEN_REVIEW v1의 replyId를 보존하고 리뷰 상세 v2 빈 payload와 OPEN_USER v1을 추가한다.
- 사용자 최신 지시에 따라 새 테이블, user_push_configs 연동, 수신 설정 API, 푸시 발송은 제외한다.
- 베스트 리뷰 선정 변경과 알림 전달 구조는 폐기했다. 기존 Batch 코드는 그대로 두고 별도 PR에서 선정 방식을 교체한다.
- 수신 설정·보관·삭제·아카이브·운영 규모 성능 목표는 후속이다. #383 전체를 완료하거나 닫지 않는다.

## Impact Scope

- mono: review/like/user 활동 이벤트와 History·Notification 리스너, 멱등 저장, Action 계약.
- product-api: 알림 OpenAPI와 활동·저장 통합 테스트.
- test-support: 기존 InMemoryNotificationRepository에 멱등 저장 포트 구현.
- CI: 원격 formatter 변경을 artifact로 수집한다.
- 스키마, Batch, ProductApplication, Admin API와 설정 API에는 최종 변경을 남기지 않는다.

## Execution Mode

- mode: delegated
- scope: plan, implement, test, self-review, verify, commit, push, pr
- verify: 원격 commit·push 후 GitHub Actions에서만 수행한다. 로컬 Docker·Testcontainers·Gradle·컴파일·테스트·빌드·포맷 실행은 금지한다. 로컬에서는 코드·diff를 정적으로 검토한다.
- completion-evidence: 최종 HEAD SHA, Actions URL, 필수 job 결과, 실제 테스트 수와 실패 수, 미검증 항목.
- stop-conditions: 승인 가정 변경 시 문서와 범위 갱신, CI 실패를 세 차례 수정으로 해결하지 못함, merge·release·배포·운영 데이터 변경 등 범위 밖 작업.
