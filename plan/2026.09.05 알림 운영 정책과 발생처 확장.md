# Plan: 알림 운영 정책과 발생처 확장 1차

Status: In Progress

## Overview

관련 이슈는 bottle-note/workspace#383이며, 댓글·좋아요 활동 이벤트 공동화를 위해 #373의 일부를 포함한다. 기존 댓글·문의 답변을 보존하면서 대댓글·리뷰 좋아요·팔로우 알림을 추가한다.

2026.09.05 사용자의 최신 지시에 따라 기존 테이블을 재사용하고 베스트 리뷰 선정 변경을 이번 PR에서 폐기한다. 기존 베스트 리뷰 배치는 그대로 유지하며 선정 방식 교체는 별도 PR에서 다룬다.

## Assumptions

1. 이번 발생처는 댓글·대댓글·리뷰 좋아요·새 팔로워·기존 문의 답변이다. 베스트 리뷰 선정·전달, 쪽지, 공지, 신고 결과, 사업자 문의 답변, 계정 제재, 팔로우한 사람의 새 리뷰는 제외한다.
2. 대댓글은 리뷰 작성자와 직접 부모 댓글 작성자에게 알리며 행위자는 제외한다. 동일 수신자는 한 건으로 합친다.
3. 좋아요·팔로우는 활성 전이에만 알림 대상이 된다. 반복 요청·취소는 생성하지 않고 재활성화해도 동일 관계의 최초 알림 한 건을 유지한다.
4. 수신 거부는 새 알림 생성에 적용하며 기존 알림·읽음 상태·History는 보존한다. 설정 활성화만으로 과거 활동을 소급하지 않는다.
5. 기존 user_push_configs는 review, follower, event, promotion, night 컬럼을 가진다. 리뷰 세부 유형과 문의 답변 독립 설정은 없다. 기존 컬럼으로 묶어 사용할지 기존 테이블 컬럼을 확장할지 사용자 확인이 필요하며, 답변 전 관련 API·저장 모델 변경은 보류한다.
6. 현재 items·envelope·필터·HMAC cursor·미읽음 집계 계약을 유지한다. totalCount를 다시 추가하지 않는다. OPEN_REVIEW v1의 replyId는 유지하고 댓글 없는 리뷰에 v2 빈 payload, 팔로우에 OPEN_USER v1을 추가한다.
7. 원본 rollback에는 알림·History를 생성하지 않는다. 댓글·좋아요는 단일 활동 이벤트를 발행하며 History와 Notification이 각자 처리한다. 한 수신자의 실패가 다른 수신자의 알림을 취소하지 않도록 저장 트랜잭션을 분리한다.
8. 보관·삭제·아카이브 정책과 운영 규모 성능 목표는 후속으로 남는다. #383 전체를 완료하거나 닫지 않는다.

## Impact Scope

- mono: notification 설정·Action·저장, review/like/user 활동 이벤트, history 리스너.
- product-api: 본인 알림 설정 API와 OpenAPI·통합 테스트.
- admin-api: 기존 문의 답변 알림 회귀 테스트.
- test-support: 설정과 저장 포트의 InMemory 구현.
- CI: 원격 포맷 결과 수집. 베스트 리뷰 전용 job 추가는 폐기한다.
- Batch와 신규 테이블은 이번 변경에서 제외한다. 기존 스키마 gitlink를 유지한다.

## Success Criteria

1. 기존 댓글과 문의 답변 계약을 유지한다.
2. 대댓글 수신자 조합에서 행위자와 중복 수신자를 제외한다.
3. 좋아요·팔로우 활성 전이와 반복·취소·재활성화 정책을 검증한다.
4. 기존 테이블을 재사용한 설정 계약이 사용자 의도와 일치하고 사용자 격리·부분 변경·동시 변경·오류 응답을 검증한다.
5. 원본 rollback, 수신자별 실패 격리, 동시 중복 전달, History 기록 조건을 통합 테스트로 검증한다.
6. 신규 Action JSON/OpenAPI와 기존 목록·읽음·cursor 계약의 회귀를 검증한다.
7. 최종 원격 HEAD와 GitHub Actions SHA가 일치하고 단위·아키텍처·Product/Admin 통합·OpenAPI·빌드가 모두 통과한다.

## Execution Mode

- mode: delegated
- scope: plan, implement, test, self-review, verify, commit, push, pr
- verify: 원격 commit·push 후 GitHub Actions에서만 실행한다. 로컬 Docker·Testcontainers·Gradle·컴파일·테스트·빌드·포맷 실행은 금지한다. 로컬에서는 코드·diff를 정적으로 검토한다.
- completion-evidence: 최종 HEAD SHA, Actions URL, 필수 job 결과, 실제 테스트 수와 실패 수, 미검증 항목.
- stop-conditions: 승인 가정 변경 시 문서 갱신 및 필요한 정책 확인, CI 실패를 세 차례 수정으로 해결하지 못함, merge·release·배포·운영 데이터 변경 등 범위 밖 작업.
