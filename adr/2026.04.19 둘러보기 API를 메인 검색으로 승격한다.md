# ADR: 둘러보기 API를 메인 검색으로 승격하고 2단계 쿼리와 seed 기반 RANDOM 정렬을 유지한다

- Decision Date(결정일): 2026.04.19 (seed 파라미터 2026.05.08, `/search` 삭제 2026.08.15)
- Scope(대상): `bottlenote-product-api`, `bottlenote-mono` alcohols 도메인
- Original Plan(원본 계획): `plan/complete/explore-as-main-search.md`, `explore-random-seed.md`, `alcohol-search-performance-improvement.md` (git 히스토리)

## Context(배경)

둘러보기와 검색이 UX상 별도 화면이었지만 개념이 겹쳤고, 단일 쿼리 방식의 검색은 느렸다. 둘러보기에 2단계 쿼리 성능 개선이 먼저 들어가 대폭 빨라졌기 때문에 그 위에 기능을 얹는 쪽이 유리했다. RANDOM 정렬은 매 요청 `RAND()`를 새로 뽑아 커서 페이지네이션에서 중복·누락이 생겼다.

## Decision(결정)

- `GET /api/v1/alcohols/explore/standard`를 메인 탐색·검색 엔드포인트로 삼고, 기존 검색의 필터(`category`, `regionIds` 복수 OR, `distilleryIds` 복수 OR, `curationId`)와 정렬(`sortType`, `sortOrder`), 응답 필드(`reviewCount`, `pickCount`)를 흡수한다.
- 조회는 2단계 구조를 유지한다. 1단계는 ID만 뽑고 2단계에서 본문을 조회하며, heavy 상관 서브쿼리가 1단계에 침투하지 않도록 `ExploreStandardQueryStructureTest`로 구조를 고정한다.
- `sortType=RANDOM`은 `ORDER BY RAND(:seed)` + `id` tie-breaker로 정렬한다. seed가 없으면 서버가 생성해 응답 meta로 돌려주고, 클라이언트는 같은 seed를 이어 보내 페이지 간 중복·누락을 없앤다.
- 검색 키워드→큐레이션 자동 매핑("비 오는 날 추천 위스키" 등)은 이식하지 않는다. `curationId`는 순수 파라미터다.
- 별도의 검색 성능 개선 계획(집계 테이블 + 검색 키워드 비정규화 + 배치 Job)은 착수하지 않는다. 둘러보기 쿼리 최적화가 같은 영역을 해소했다.
- `/api/v1/alcohols/search`는 keyset cursor 전환(#402) 때 삭제했다.

### Rejected Alternatives(선택하지 않은 대안)

- 검색 API를 별도로 최적화(집계 테이블 + 배치): 둘러보기 보강으로 자연 해소되어 종결. 정량 측정이 필요해지면 재개한다.
- RANDOM 결과를 서버 캐시에 고정: 다중 인스턴스에서 세션 상태를 공유할 수 없어 seed 에코 방식을 택했다.

## Status(상태)

Accepted(승인됨)

- Implementation Record(적용 기록): 적용됨

## Consequences(결과와 영향)

- 탐색 엔드포인트 하나가 필터·정렬·검색을 모두 지원하므로 QuerySupporter가 무거워졌다. 구조 테스트가 회귀 방어선이다.
- 이후 리뷰 둘러보기 계약과 검색 결과 집합 규칙은 별도 ADR(2026.08.21, 2026.09.05)로 확장했다.
