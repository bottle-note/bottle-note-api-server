# ADR: 지역은 parent_id 자기 참조로 계층화한다

- 상태: 적용됨
- 결정일: 2026.04.05
- 대상: `bottlenote-mono` alcohols 도메인, `git.environment-variables`
- 원본 계획: `plan/complete/region-hierarchy.md` (git 히스토리)

## 결정

- `Region`에 `parent_id` self-reference(`@ManyToOne`)를 추가해 FK 기반 부모-자식 관계를 둔다.
- 부모 지역(예: "스코틀랜드/전체", id=19)으로 검색하면 자기 자신과 하위 지역(캠벨타운, 아일라, 스페이사이드 등)의 위스키를 함께 조회한다.
- 별도 Resolver 클래스를 만들지 않고 `AlcoholQuerySupporter` 등 QuerySupporter의 `eqRegion` 안에서 `RegionRepository.findChildRegionIds`를 호출해 하위 지역을 해석한다.
- 응답(`RegionsItem`, `AdminRegionItem`)에 `parentId`를 노출한다.

## 배경

지역이 플랫 구조여서 스코틀랜드 하위 지역이 독립 레코드로만 존재했고, "스코틀랜드"를 고르면 하위 지역 위스키가 빠졌다. 미국·일본 등 다른 국가에도 같은 패턴을 적용할 수 있어야 했다.

## 선택하지 않은 대안

- 코드 상수나 별도 매핑 테이블로 그룹 정의: 데이터 무결성을 FK로 보장할 수 없어 제외했다.
- 계층 해석 전용 클래스 추가: 호출 지점이 QuerySupporter 3곳뿐이라 추상화 비용이 더 컸다.

## 결과와 비용

- 지역 필터를 쓰는 조회(`regionIds` 복수 OR 포함)는 항상 자식 확장 후 `IN`으로 실행된다.
- 계층은 1단계만 실사용 중이며 다단계 재귀는 구현하지 않았다.
