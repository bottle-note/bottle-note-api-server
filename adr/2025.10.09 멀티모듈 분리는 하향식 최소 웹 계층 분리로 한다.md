# ADR: 멀티모듈 분리는 top-down 최소 웹 계층 분리로 한다

- 상태: 적용됨
- 결정일: 2025.10.09
- 대상: `bottlenote-product-api`, `bottlenote-mono`, 이후 `bottlenote-admin-api`, `bottlenote-batch`
- 원본 계획: `plan/complete/migration.v1.0.1.md` ~ `migration.v2.0.1.md` (git 히스토리)

## 결정

단일 모듈을 클린 아키텍처식 계층 모듈(presentation / application / domain / infrastructure / shared)로 bottom-up 분리하려던 v1 계획을 폐기하고, 웹 진입점만 최소로 떼어내는 top-down 분리를 채택한다.

- `bottlenote-product-api`: 컨트롤러, `@RestControllerAdvice`, Spring Boot main, 웹 필터, `SecurityConfig`·`WebConfig`만 둔다.
- `bottlenote-mono`: 도메인, DTO(request/response 포함), Service/Facade/Repository, Exception 전부를 둔다.
- 의존 방향은 `product-api → mono` 단방향이다. DTO는 순환 의존을 막기 위해 mono에 남긴다.
- 이후 admin-api(Kotlin)와 batch도 같은 방식으로 mono를 소비하는 실행 모듈로 추가한다.

## 배경

v1 계획(core / shared / legacy 분리)은 하위 계층부터 옮기는 방식이었고, 실제 시도에서 순환 의존이 반복됐다. 대표 사례가 `RatingPoint`다. 도메인 VO를 core로 옮기면 `RatingException`이 따라가야 하고, 웹 변환기 `RatingPointConverter`는 legacy에 남아 core를 참조하며, `WebConfig`가 그 Converter를 등록하면서 legacy → core → shared → core 순환이 생겼다. DTO 수준에서도 같은 중첩 참조가 있었다. 웹 계층 Converter가 도메인 객체와 예외를 모두 알아야 하는 구조에서는 계층별 분리가 필연적으로 순환을 만든다는 것이 확인됐다.

## 선택하지 않은 대안

- 클린 아키텍처 4계층 + shared 모듈(v1.0.1~v1.0.5): 순환 의존과 DTO 중첩 참조로 진행 불가. 포트/어댑터로 우회하려 했으나 이관 비용이 과도했다.
- mono를 `bottlenote-domain`·`bottlenote-core-business` 등으로 개명: 이름만 바뀌고 책임은 같아 보류했다.

## 결과와 비용

- 순환 의존 없이 실행 모듈(product-api, admin-api, batch)을 추가할 수 있게 됐다. 현재 토폴로지는 `CLAUDE.md`의 모듈 구조 절이 기준이다.
- mono가 거대한 공유 라이브러리로 남는다. 도메인 간 경계는 모듈이 아니라 패키지 규칙과 ArchUnit(레이어 표준 15)으로 강제한다.
- 이후 물리 3분할은 트리거 조건부로 강등했다(2026.06.10, `CLAUDE.md`).
