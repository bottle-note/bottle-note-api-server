# ADR: 둘러보기 검색·정렬·별점 파라미터 규칙과 리뷰 위치 정보 노출 계약

- 상태: 적용됨
- 결정일: 2026.08.21
- 대상: `bottlenote-product-api`, `bottlenote-mono` alcohols·review 도메인
- 관련 이슈·PR: `bottle-note/workspace#414`, `#415`, `#417`, `#419`, `bottle-note/bottle-note-api-server#713`, `#714`
- 원본 계획: `plan/explore-search-sort-rating-contract.md`, `review-explore-location-contract.md` (git 히스토리)

## 결정

- 리뷰 둘러보기 검색은 단일 `keyword`다. 기존 다중 `keywords`(AND 결합)는 `keyword`가 없을 때만 기존 의미로 처리하고 OpenAPI에 `deprecated`로 표시한다. 둘을 함께 보내면 400이다. 제거 시점은 약속하지 않는다.
- 별점 필터 `rating`은 0.5 이상 5.0 이하 0.5 단위만 유효하다. NaN, Infinity, 범위 밖, 0.5 단위가 아닌 값은 400이며 검증은 부동소수점 나머지가 아니라 `BigDecimal` 등가로 한다. "전체"는 별도 값이 아니라 파라미터 생략이다.
- 위스키 둘러보기의 별점 필터는 목록에 표시되는 집계 평점과 같은 반올림 기준으로 HAVING 조건에 적용한다. 리뷰 둘러보기는 각 리뷰의 작성 평점(`review.reviewRating`) 정확값 기준이다. RANDOM 후보 조회에도 rating 조건을 적용한다.
- 리뷰 둘러보기 무파라미터 기본 정렬은 `LATEST + DESC`(`createAt DESC, id DESC`)다. `ReviewPageableRequest`를 쓰는 술별·내 리뷰 목록의 `POPULAR` 기본값은 바꾸지 않는다. 지원 값은 `ReviewSortType`·`SortOrder` enum이 SSoT이고 알 수 없는 값은 임의 기본값으로 폴백하지 않는다.
- 모든 정렬은 결정적 tie-breaker로 review/alcohol ID를 포함하고, 방향이 바뀌면 tie-breaker 방향도 같이 바뀐다.
- 리뷰 둘러보기 카드에 `locationInfo`를 노출한다. 소스는 별도 Bar 도메인이 아니라 `Review.reviewLocation` embedded 컬럼이며 기존 `LocationInfo` 구조(`locationName`, `zipCode`, `address`, `detailAddress`, `category`, `mapUrl`, `latitude`, `longitude`)를 재사용한다. 모든 컬럼이 비면 빈 객체가 아니라 `null`, 일부만 있으면 객체에 미입력 필드 `null`이다. 위치는 keyword 검색 범위에 넣지 않는다.

## 배경

workspace#414/415/417은 위스키·리뷰 둘러보기의 검색·정렬·별점 계약을 일관되게 맞추는 요청이었고, 기존 리뷰 다중 키워드 소비자를 즉시 끊을 수 없었다. #419는 "바 엔티티 연결"로 읽힐 수 있었지만 실제로는 리뷰에 이미 저장된 주소·상호를 노출하는 작업이었다.

## 선택하지 않은 대안

- `keywords` 즉시 제거: 소비자 전환 기간이 필요하다.
- `keyword`와 `keywords` 동시 허용: 우선순위가 모호해 400으로 닫았다.
- 별점 "전체"를 문자열 값으로 표현: 생략이 더 단순하다.
- Bar 엔티티·외부 API 도입: 범위와 데이터 모델을 키우고 이번 요구에 불필요하다.

## 결과와 비용

- 리뷰 둘러보기와 위스키 둘러보기의 평점 의미(작성 평점 vs 집계 평점)와 쿼리 구현은 분리해서 유지한다. 공통화는 입력 값 규칙처럼 실제 중복이 확인된 부분에만 한다.
- 인증 정책, endpoint 경로, cursor 응답 구조는 이 결정에서 바꾸지 않았다.
