# ADR: 캠페인 콘텐츠 참여는 전용 이벤트 테이블에 기록하고 방문자 ID는 필터가 요청 전에 확정한다

- Decision Date(결정일): 2026.09.15
- Scope(대상): `bottlenote-observability`, `bottlenote-mono` campaigncontent·statistics, `bottlenote-product-api`, `bottlenote-admin-api`
- Related Issues(관련 이슈): `bottle-note/workspace#471`(백엔드), `bottle-note/workspace#472`(FE)
- Related ADR(관련 ADR): [방문자 식별은 서버 발행 쿠키로 하고 인증에 쓰지 않는다](<2026.07.16 방문자 식별은 서버 발행 쿠키로 하고 인증에 쓰지 않는다.md>), [통계 시계열은 표준 포맷 하나로 내리고 열린 버킷은 읽기 시점에 롤다운한다](<2026.09.07 통계 시계열은 표준 포맷 하나로 내리고 열린 버킷은 읽기 시점에 롤다운한다.md>)

## Context(배경)

FE는 위스키 MBTI(`/whiskey-mbti`), 위스키 타로(`/whiskey-tarot`)처럼 백엔드 없이 콘텐츠를 만들어 배포한다. 서버에 참여 기록이 남지 않아 콘텐츠별 참여율을 판단할 수 없었다. 이런 콘텐츠를 도메인에서 "캠페인 콘텐츠"(`CampaignContent`)라 부르기로 했고, 결과 보기는 모든 캠페인 콘텐츠에서 로그인 후에만 가능하도록 정했다.

비로그인 참여자를 이을 식별자가 필요했다. 방문 텔레메트리는 이미 `__Host-bn-visitor-id` 쿠키를 발급하지만, `VisitorTelemetryFilter`는 요청 처리가 끝난 뒤에야 쿠키를 읽고 발급했다. 핸들러는 그 값을 받을 수 없었고, 쿠키 없는 첫 요청에는 식별값 자체가 없었다. 캠페인 페이지는 백엔드를 거의 호출하지 않아 `VIEW`가 첫 API 요청이 되는 경우가 많다.

참여율 분모와 봇·내부 IP 제외는 방문자 통계(statistics 도메인)의 기준과 같아야 했다. 제외 규칙 설정 `bottlenote.statistics.exclusion`은 statistics 도메인 소유다.

## Decision(결정)

### 참여 기록

- 이벤트는 `campaign_content_events`에 추가 전용으로 기록한다. 유형은 `VIEW`(첫 진입), `START`(시작), `FINISH`(완료, 로그인 요구 직전), `RESULT`(로그인 상태에서 결과 노출)다.
- 수집 API는 `POST /api/v1/campaign-contents/{code}/events`(`OPTIONAL_AUTH`)이며 body는 `{ "type": ... }`뿐이다. 누가·언제는 서버가 채운다.
- `RESULT`를 회원 없이 보내면 기존 API와 같은 `REQUIRED_USER_ID`(400)로 거절한다. 미등록·비활성 코드는 모두 404다.
- 코드는 어드민이 등록하고 등록 후 바꿀 수 없다. 참여 기록이 있는 캠페인 콘텐츠는 삭제하지 않고 비활성화한다(FK `RESTRICT`).
- 이벤트에는 회원 ID와 함께 방문자 해시, 정규화 IP, 기기 유형을 남긴다. 값은 모두 방문자 필터가 텔레메트리와 같은 방식으로 만든 것을 쓴다(`HttpClient.getClientIP` 사용 금지).

### 방문자 식별

- 참여 토큰 같은 별도 세션 식별자는 만들지 않고 방문자 쿠키를 재사용한다. 도메인에는 원본 UUID가 아니라 텔레메트리와 같은 SHA-256 해시를 저장한다.
- `VisitorTelemetryFilter`는 필터 체인 순서를 바꾸지 않고, 요청 처리 전에 방문자 ID를 확정한다. 유효한 쿠키가 있으면 그 값, 없거나 형식이 틀리면 새 UUID를 쓴다.
- 확정한 해시·IP·기기 유형을 `VISITOR_ID_ATTRIBUTE`, `CLIENT_IP_ATTRIBUTE`, `DEVICE_TYPE_ATTRIBUTE` 요청 속성으로 싣는다. 응답이 2xx이고 요청에 유효 쿠키가 없었으면 같은 UUID로 쿠키를 발급하고 텔레메트리도 같은 값으로 발행한다.
- 방문자 식별값은 익명 참여를 잇는 상관키로만 쓴다. 인증·권한 판단에는 쓰지 않는다는 2026.07.16 결정은 유지한다.

### 지표

- 진입·시작·완료는 순방문자, 결과 조회는 순회원 기준이다.
- 완주율은 기간 안에서 `START`와 `FINISH`가 모두 있는 방문자 / `START` 방문자, 로그인 전환율은 `FINISH`와 `RESULT`가 모두 있는 방문자 / `FINISH` 방문자다. 교집합을 같은 `visitor_id` 안에서 판정해 기간·기기 경계에서 100%를 넘지 않게 한다.
- 참여율은 `RESULT` 순회원 / 같은 기간 서비스 전체 순 활성 회원이다. 분모는 `VisitorStatisticsFacade.countActiveMembers`로 받는다.
- 제외 규칙은 `VisitorStatisticsFacade.getExclusion`으로 받아 캠페인 집계 SQL에도 같은 조건(기기 유형, `ip_address IS NOT NULL`, IP 대역, `root_admins`)으로 적용한다. 설정은 statistics에 두고 캠페인 도메인은 Facade로만 접근한다.
- 지표 기간은 오늘을 포함한 최근 90일 안이어야 한다. 방문 텔레메트리 보존 기간과 같다. 목록의 "최근 7일 참여자"는 `RESULT` 순회원이다.
- 공개 POST에는 access-control path-rule로 IP당 분당 60건 한도를 둔다.

### FE 계약

- 이벤트는 브라우저에서 같은 origin의 `/bottle-api`로 직접 보낸다. SSR·Route Handler·서버 프록시로 보내면 쿠키가 없고 IP가 Next 서버 대역이라 지표에서 빠진다.
- 처음 방문한 사용자는 다른 API 응답으로 쿠키를 받은 뒤 `VIEW`를 보낸다. 병렬 첫 요청은 응답마다 다른 쿠키를 받아 방문자가 갈라지며, 요청 간 경쟁이라 서버에서 막을 수 없다.

### Rejected Alternatives(선택하지 않은 대안)

- 방문 텔레메트리 재사용(경로에 유형을 넣고 `visitor_telemetry_events`에서 집계): 코드가 가장 적지만 요청 로그를 도메인 데이터로 쓰게 되고, Redis Stream·batch 적재 지연과 경로 변경에 지표가 묶인다.
- `START`에서 참여 토큰 발급: 회차별 분석과 위조 방지는 얻지만 FE가 로그인 이동 전후로 토큰을 보존해야 하고, 합의한 지표는 모두 기간 내 순방문자·순회원이라 필요하지 않다.
- 제외 규칙 설정을 `global`로 이동: 참조 경로 하나를 위해 statistics 코드와 2026.09.07 ADR을 함께 바꿔야 한다.
- statistics가 캠페인 지표를 계산: statistics가 캠페인 테이블을 읽어 레이어 표준 5를 어긴다.
- 필터의 User-Agent 해석 로직을 공용 클래스로 추출: 요청 속성으로 결과만 넘기면 파서를 필터 안에 둘 수 있다.

## Consequences(결과와 영향)

- 첫 방문의 `VIEW`도 이후 이벤트와 같은 방문자로 이어진다. 방문자 필터가 꺼진 환경(기본값 `enabled=false`, 테스트 프로파일)에서는 방문자·IP·기기 유형이 비어 저장되고 제외 규칙의 `ip_address IS NOT NULL`에 걸려 지표에서 빠진다.
- 제외 조건 SQL이 `JdbcVisitorStatisticsRepository`와 `JdbcCampaignContentMetricsRepository`에 나뉘어 있다. 규칙 값은 설정 한 곳에서 오지만 조건 종류가 늘면 두 곳을 함께 고친다.
- 오늘 지표의 참여율 분모는 텔레메트리 적재 지연으로 잠정치이며, 적재가 늦으면 일시적으로 100%를 넘을 수 있다.
- 쿠키 삭제, 다른 브라우저, 카카오톡 인앱 브라우저에서 외부 브라우저로 넘어가는 로그인은 방문자가 끊겨 로그인 전환율이 낮게 잡힐 수 있다. WebView 쿠키 왕복 검증과 개인정보 처리방침 반영은 2026.07.16 ADR의 운영 후속 항목으로 남는다.
- 도메인 테이블에 방문자 해시와 회원 ID를 함께 남기는 첫 사례다. 해시만 저장하고 원본 쿠키 값은 요청 속성에도 싣지 않는다.
