# 업무 경계를 Gradle 모듈로 분리하고 기존 배포 단위는 유지한다

- Decision Date(결정일): 2026.11.17
- Scope(대상): 기존 `bottlenote-mono`에서 옮긴 업무 코드와 공통 코드, 세 실행 앱이 build 파일에 적는 모듈 의존
- Related ADRs(관련 문서): [멀티모듈 분리는 하향식(top-down) 최소 웹 계층 분리로 한다](<2025.10.09 멀티모듈 분리는 하향식 최소 웹 계층 분리로 한다.md>), [모듈 간 협력은 공개 계약과 단방향 의존으로 구성한다](<2026.11.17 모듈 간 협력은 공개 계약과 단방향 의존으로 구성한다.md>), [업무 Fake와 fixture는 소유 모듈에 두고 테스트 인프라는 공유한다](<2026.11.17 업무 Fake와 fixture는 소유 모듈에 두고 테스트 인프라는 공유한다.md>)

## Context(배경)

과거에는 세 앱이 mono 전체를 공유했다. 업무 간 참조를 build에서 구분하기 어려웠다. 업무별 변경 범위와 허용된 의존을 드러내되 HTTP 계약, DB 스키마와 기존 세 배포 단위는 유지하기로 했다.

## Decision(결정)

현재 `settings.gradle`에는 16개 모듈이 있다. `bottlenote-mono`의 소스와 build 설정은 제거했다. Gradle 프로젝트명에는 `bottlenote-` 접두사를 붙인다.

| 모듈 | 소유하는 코드 |
|---|---|
| product-api / admin-api / batch | 기존 3개 실행 앱. Product·Admin의 화면별 복합 조회와 응답 조합도 각 앱이 소유한다 |
| foundation | 업무 타입과 업무 테이블을 모르는 공통 기반, 공통 예외·페이징·JPA 설정·외부 연동 |
| user | 사용자·인증·약관·차단·감사자·마스킹 |
| alcohol | 주류·속성·기존 큐레이션(AdminCurationService)·수입 정보와 주류 병합 계약 |
| storage | 파일·이미지·리소스 기록 |
| community | 리뷰·별점·좋아요·찜과 관련 웹 변환 설정 |
| history | 활동 이력과 Redis 주류 조회 이력 |
| support | 문의와 일일 리포트 |
| notification | 알림과 수신 설정 |
| analytics | 방문·통계 |
| content | 배너·캠페인·스펙 기반 큐레이션(AdminSpecBasedCurationService) |
| access-control | IP 접근 제어 |
| observability | 관측 공통 기능 |
| test-support | 업무를 모르는 컨테이너 설정·데이터 정리·webhook 테스트 대역 |

실행 앱 3개는 루트에 둔다. 업무 모듈 10개는 `module-domains/{이름}`, foundation·observability·test-support는 `module-shared/{이름}`에 둔다. `settings.gradle`에서 각 폴더를 기존 Gradle 프로젝트명에 `projectDir`로 연결한다.

모듈명은 패키지명과 같지 않을 수 있다. 파일 위치와 build 의존을 함께 확인한다. `query`와 `web-support` 모듈은 만들지 않았다. 조회는 사용하는 앱에 두고, 인증과 마스킹은 user에, 별점 규칙과 웹 변환 설정은 community에 두었다.

운영 코드의 허용 방향은 다음과 같다. 화살표는 왼쪽이 오른쪽 타입을 사용한다는 뜻이며 업무의 중요도와 무관하다. 모든 업무 라이브러리는 foundation을 `api`로 공개하고, 그 밖의 업무 간 의존은 `implementation`으로 선언한다.

- foundation → observability
- user, alcohol, analytics → foundation
- storage → foundation, user
- community → foundation, user, alcohol, storage, observability
- history → foundation, user, alcohol, community, observability
- support → foundation, user, community
- notification → foundation, user, community, support
- content → foundation, user, alcohol, community, analytics
- access-control → foundation, user

Product와 Admin은 필요한 업무 라이브러리를 직접 선언한다. 두 앱은 서로를 의존하지 않는다. Batch main은 foundation, alcohol, community, support를 직접 선언하고 test에서는 user도 직접 쓴다.

계층별로 모듈을 나누지 않는다. Service·Repository·모델은 같은 업무의 소유 모듈에 둔다. foundation에 넣을 때는 업무 타입 import뿐 아니라 업무 테이블 SQL도 없는지 확인한다.

이 결정은 서비스나 DB 분리가 아니다. Product, Admin, Batch의 기존 배포 방식과 DB를 유지한다. 변경된 모듈만 감지해 이미지를 빌드하는 방식은 이번에 구현하지 않았다.

### Rejected Alternatives(선택하지 않은 대안)

mono 유지, 모든 업무의 계약/구현 모듈 쌍 생성, 별도 공유 query 모듈 생성은 선택하지 않았다. 실제 호출과 조회 소유를 정리해 순환을 없앴다.

## Status(상태)

Superseded(대체됨)

- Replacement(대체 문서): [admin API를 product 배포 단위로 흡수하고 섀도우 검증 뒤 admin 앱을 제거한다](<2026.11.19 admin API를 product 배포 단위로 흡수하고 섀도우 검증 뒤 admin 앱을 제거한다.md>)

- Implementation Record(적용 기록): 사용자가 위임한 구현 범위에서 2026.11.17에 적용했다. 현재 작업 트리는 미커밋 상태다.
- 검증 근거: 최종 빌드 검사자의 결과를 읽어 확인했다. 지정한 로컬 사례 2,346개 중 2,345개 통과, 기존 성능 측정 1개 건너뜀, 남은 실패·오류 0개다. 이 문서 작성자는 Gradle을 실행하지 않았다.
- 검증 입력은 서브모듈 `e1beb652`의 SQL 32개 snapshot이다. 생성 리소스는 기존 로컬 SQL 30개 상태로 복원했다. 로컬 SQL 30개로 같은 검사가 통과했다는 뜻은 아니다. 기존 dirty gitlink는 보존했다.
- 원격 CI, 배포, 전체 성능, 선택하지 않은 전체 테스트는 미검증이다.

### Revision History(개정 이력)

- 2026.11.19: 기존 배포 단위를 유지한다는 결정만 [admin API를 product 배포 단위로 흡수하고 섀도우 검증 뒤 admin 앱을 제거한다](<2026.11.19 admin API를 product 배포 단위로 흡수하고 섀도우 검증 뒤 admin 앱을 제거한다.md>)로 대체되었다. 업무 경계를 Gradle 모듈로 분리한 결정(모듈 구성, 위치, 의존 방향)은 계속 유효하며, 모듈 구조는 이 문서와 프로젝트 지침을 그대로 따른다.

## Consequences(결과와 영향)

build 선언에서 업무 간 의존을 확인할 수 있다. 선언하지 않았고 전이 의존으로도 노출되지 않은 타입은 컴파일할 수 없다. 그러나 `implementation`은 의존 대상 모듈의 public 내부 클래스를 숨기지 않는다. 공개 계약 밖 접근과 조회의 쓰기 금지는 규칙 검사와 리뷰가 맡는다. 모듈 분리가 잘못된 변경이나 AI가 만든 코드를 모두 차단하지는 않는다.

build와 fixture 설정이 늘었다. 여러 모듈이 쓰는 계약을 바꾸면 소비자도 함께 고쳐야 한다. 빌드 시간·비용 절감은 측정하지 않았다. 과거 웹 계층만 분리하던 [2025.10.09 결정](<2025.10.09 멀티모듈 분리는 하향식 최소 웹 계층 분리로 한다.md>)을 대체한다. 협력은 [모듈 간 협력은 공개 계약과 단방향 의존으로 구성한다](<2026.11.17 모듈 간 협력은 공개 계약과 단방향 의존으로 구성한다.md>), 테스트는 [업무 Fake와 fixture는 소유 모듈에 두고 테스트 인프라는 공유한다](<2026.11.17 업무 Fake와 fixture는 소유 모듈에 두고 테스트 인프라는 공유한다.md>)를 따른다.
