# ADR: batch 배포 버전은 저장소 `VERSION` 파일이 아니라 배포자가 입력하는 exact SemVer로 한다

- 상태: 적용됨
- 결정일: 2026.07.23
- 대상: `.github/workflows/deploy_batch.yml`, `.agents/skills`·`.claude/skills`의 deploy-batch 스크립트
- 원본 계획: `plan/complete/batch-version-policy.md` (git 히스토리)

## 결정

- `bottlenote-batch/VERSION` 파일을 삭제하고, `deploy_batch.yml`의 `workflow_dispatch`가 필수 `version` 입력을 받는다. 형식은 prerelease·build metadata가 없는 exact `X.Y.Z`만 허용하며, 이미지 태그는 `batch_X.Y.Z`다.
- 기준 버전은 `environment-variables` 최신 `origin/main`의 development·production overlay에 선언된 batch 태그 중 SemVer 최댓값이고, 입력값은 이보다 커야 한다. 비교는 문자열이 아니라 major/minor/patch 숫자 비교다.
- registry에 같은 태그가 이미 있으면 prepare와 push 직전 두 단계에서 차단하고 덮어쓰지 않는다.
- production 배포는 `main`에서만 허용한다.
- 로컬 `deploy-batch` 스킬은 patch +1을 기본 추천값으로 제시하고 선택한 exact 버전을 build/push/kustomize 전 단계에 전달한다.

## 배경

`VERSION` 파일이 source of truth일 때는 배포마다 파일을 올려 커밋해야 했고, 실패 재시도 안내도 "VERSION을 증가시켜라"였다. 실제 배포된 버전은 overlay에 있으므로 그것을 기준으로 삼는 편이 정확하다.

## 선택하지 않은 대안

- 워크플로가 버전을 자동 계산: 배포자가 의도한 버전과 어긋날 수 있어 입력값만 소비한다.

## 결과와 비용

- 배포 명령은 `gh workflow run deploy_batch.yml -f environment=production -f version=X.Y.Z`다(`CLAUDE.md`).
- `.agents`와 `.claude`의 스크립트는 바이트 단위로 같아야 한다.
