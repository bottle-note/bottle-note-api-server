# ADR: 접근 정책은 @SecurityPolicy 선언으로 관리하고 누락 시 인증 필수로 닫는다

- 상태: 적용됨
- 결정일: 2026.06.04
- 대상: `bottlenote-mono` global.security, `bottlenote-product-api`, `bottlenote-admin-api`
- 원본 계획: `plan/complete/jwt-access-policy-declaration.md` (git 히스토리)

## 결정

- 엔드포인트 접근 정책을 `public`, `optional-auth`, `required-auth` 세 가지로 두고 handler에 `@SecurityPolicy`로 선언한다. `SecurityPolicyRegistry`가 handler mapping을 수집해 `SecurityPolicyRoute`로 만든다.
- 어노테이션이 없는 handler는 `required-auth`로 fallback한다. 새 endpoint를 추가하면서 정책을 빠뜨리면 열리는 게 아니라 닫힌다.
- `JwtAuthenticationFilter`는 public 경로만 건너뛰고, optional/required에서는 토큰이 있으면 사용자 컨텍스트를 세팅한다. optional-auth에 잘못된 토큰이 오면 무시하지 않고 401로 차단한다.
- 수집된 handler가 없는 경로(404, 정적 리소스)는 handler fallback과 분리해 인증을 강제하지 않는다. 여러 mapping이 겹치면 Spring `PathPattern` specificity로 가장 구체적인 정책을 고른다.
- 악성 경로 denyAll과 GraphQL/GraphiQL 외부 차단은 유지한다. `SecurityConfig`의 문자열 matcher 생성은 제거하고 정책 predicate로 연결한다.
- `JwtAuthenticationEntryPoint`는 인증 실패를 resolver로 넘겨 500으로 바꾸지 않고 401 JSON을 직접 만든다.

## 배경

public 경로 목록이 `SecurityConfig`의 static 배열과 필터의 skip 조건에 흩어져 있어 endpoint를 추가할 때 두 곳을 맞춰야 했고, 누락하면 기본이 열리는 쪽이었다. Spring pattern matcher와 필터의 문자열 비교가 어긋나는 문제도 있었다.

## 선택하지 않은 대안

- 기존 접근 어노테이션 + static product 정책 유지: 사용자 요청으로 제거하고 handler mapping 수집 구조로 전환했다.
- 누락 시 public fallback: 편의는 있으나 보안 기본값이 열리는 쪽이라 채택하지 않았다.

## 결과와 비용

- 무인증으로 열어야 하는 리소스(예: `/openapi.product.json`)는 반드시 PUBLIC을 명시해야 한다.
- admin-api의 login/refresh public, 나머지 authenticated 흐름은 같은 registry로 판별된다.
- 검증은 `SecurityPolicyRegistryTest`, `JwtAuthenticationFilterPolicyTest`, `MaliciousPathPatternTest`, product `SecurityConfigIntegrationTest`가 담당한다.
