# ADR: 알코올 벌크 등록은 Excel과 JSON 두 경로가 같은 검증·저장 계약을 공유한다

- Decision Date(결정일): 2026.09.05
- Scope(대상): `bottlenote-mono` alcohols 도메인(bulk DTO·정규화·서비스), `bottlenote-admin-api`(Excel·bulk 컨트롤러, OpenAPI)
- References(관련): GitHub Actions ci pipeline run `33942921473`(구현 커밋 `359e058a`)
- Original Plan(원본 계획): `plan/2026.09.05 알코올 벌크 등록.md`, `plan/admin-alcohol-xlsx-import.md` (git 히스토리)

## Context(배경)

Admin 알코올 등록은 `POST /v1/alcohols` 단건뿐이었고, 앞선 XLSX 계획(`admin-alcohol-xlsx-import`)은 템플릿 다운로드와 업로드 검증까지만 다뤘다. 실제 일괄 등록을 붙이면서 Excel 파서와 저장 로직이 묶이지 않도록 공통 JSON 입력을 중간 계약으로 두었다. 벌크 저장에서 사용자가 검증 응답을 변조해 보낼 수 있으므로 저장 측 재검증이 필요했다.

## Decision(결정)

- 등록 경로는 두 가지다. `Excel 템플릿 생성 → 검증 → 벌크 저장`과 `JSON 구조 데이터 → 검증 → 같은 벌크 저장`. 저장 서비스는 Excel 형식에 종속되지 않고, Excel은 공통 입력으로 변환하는 어댑터다.
- 계약은 `GET /admin/api/v1/alcohols/excel/template`, `POST .../excel/validate`(기존 응답 유지 + 행별 `normalized`와 `clientRowId` 추가), `POST .../bulk/validate`(상태 변경 없음), `POST .../bulk`(재검증 후 전체 저장)다. 성공은 `data.createdRows`, `data.rows(clientRowId, alcoholId)`, `data.validation`, 검증 실패는 400 `success=false` + 검증 결과다.
- 최대 1,000행을 동기 처리하며 전체 사전 검증 후 하나의 트랜잭션으로 저장한다. 오류가 한 행이라도 있으면 0건 저장하고 저장 중 예외는 전체 롤백한다.
- 저장 시 검증 응답의 valid 플래그를 신뢰하지 않고 전체 값을 재검증한다. `clientRowId`는 호출자 지정 식별자로 요청 내 유일해야 하며 Excel은 원본 행 번호를 쓴다.
- 이름·유효 enum·저장 가능한 값·참조 ID(region, distillery, tastingTag)는 오류로 거절한다. 파일 내·DB 중복 후보, 참조에 없는 category, 비표준 범위·세트 표기, 중복 태그 제거는 경고로 반환하고 저장은 허용한다. 기존 DB 데이터는 변경하지 않으며 자동 병합하지 않는다. 중복 정리는 사용자가 추후 수행한다.
- 도수는 `%`, 용량은 `ml`로 정규화한다(40, 40.00, 40% → 40%; 700, 700ml, 70cl, 0.7L → 700ml). `type`은 문자열로 받아 기존 `AlcoholType`의 unknown→WHISKY fallback을 거치지 않는다. `categoryGroup` 생략 시 정확히 하나인 category reference로 도출하고 non-WHISKY는 OTHER 기본값을 허용하며 추론 불가한 WHISKY group은 오류다.
- age/cask/description/image는 선택이다. 이미지는 기존 업로드 viewUrl만 받고 bytes 업로드는 없다. 반복 POST는 새 등록이며 import session·멱등성 저장소는 두지 않는다.
- Excel은 데이터 시트·헤더를 검사하되 안내문 텍스트, 보조 시트 순서, 추가 메모 시트는 허용하고 수식·외부 링크·미지원 데이터 열은 거절한다. 새 템플릿은 설명 행에 defined name을 기록해 행 삭제·이동을 식별하고, 기존 템플릿은 알려진 설명 문구 또는 빈 설명 행으로 식별하며 식별 불가 시 재다운로드 안내 오류를 반환한다.
- 새 스키마, category 테이블, JPA 엔티티·마이그레이션 변경은 없다.

### Rejected Alternatives(선택하지 않은 대안)

- Excel 전용 저장 서비스: 대시보드나 스크립트가 JSON으로 같은 경로를 쓸 수 없다.
- 행 단위 부분 저장: 어느 행이 들어갔는지 추적하는 부담이 크고 사용자가 원하는 것은 전부 아니면 0건이다.
- 중복·카테고리 불일치 자동 병합: 기존 데이터를 조용히 바꾸게 되어 경고로만 남긴다.
- import session과 멱등성 키: 이번 범위에 불필요한 저장소가 늘어난다.
