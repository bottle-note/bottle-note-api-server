# 주류 속성은 값과 조건을 가진 공통 사전과 수동 매핑으로 관리한다

- Decision Date(결정일): 2026.10.16
- Scope(대상): 주류 속성 사전, 술별 연결, 어드민 벌크 API
- Related(관련): environment-variables PR #35, V25

## Context(배경)

술별 EAV 행은 저장에는 단순하지만, 기획자가 공통 속성을 등록하고 연결된 술을 관리하기 어렵다. 가격도 단순 입력 항목이 아니라 `15,000원`, `15,000원 이상`처럼 값·조건을 포함한 독립 속성으로 관리한다. 기존 속성 데이터는 폐기하기로 결정했다.

## Decision(결정)

- `alcohol_attributes`가 고정 key, 관리자용 displayName, 설명, 분류, 자료형, 비교 조건, 값, 단위를 소유한다. 술과의 연결은 `alcohol_attribute_mappings`가 소유한다.
- 두 엔티티는 BaseEntity를 상속하고 생성·최종 수정 시각과 작업자 ID·유형·이메일을 기록한다.
- 속성 벌크 요청은 같은 key의 ID와 생성 정보를 유지하고 전체 갱신한다. 다른 키의 표시명 중복은 오류다. 하나의 요청에서 정규화한 key가 중복되면 거부하며, 이름 충돌 시 요청 전체를 롤백한다. 이름 교환처럼 중간 유일 제약에 걸리는 변경도 충돌로 처리한다.
- 매핑 벌크 요청은 주류 ID·속성 ID 쌍을 받는다. 기존 연결과 요청 내 중복은 감사 정보도 변경하지 않고 건너뛴다. 같은 술에 대한 등록은 정렬된 주류 행의 DB 잠금으로 직렬화한다.
- 비교 조건은 속성의 의미이며 자동 매핑 규칙이 아니다. 속성 변경 뒤에도 연결을 유지하고 적절성은 관리자가 판단한다.
- 속성 삭제는 모든 관련 매핑을 제거하고, 매핑 삭제는 속성을 보존한다. 맛 태그·맛 그룹 모델은 변경하지 않는다.

## Status(상태)

Accepted(승인됨). V25는 environment-variables PR #35로 병합되었다. 실제 환경 적용은 애플리케이션 배포와 별도로 확인한다.

## Consequences(결과와 영향)

공통 이름과 의미를 한 곳에서 수정할 수 있고 미연결 속성을 미리 등록할 수 있다. 대신 연결을 관리하는 API와 화면이 필요하다. 기존 alcoholId·basedAt 기반 속성 요청·응답은 새 사전·매핑 계약으로 전환해야 한다. V25는 기존 속성 데이터를 삭제하므로 구버전 애플리케이션과 혼용할 수 없다.
