# ADR: 로그인은 카카오·애플 v2로 단일화하고 v1 oauth·BASIC 경로를 제거한다

- Decision Date(결정일): 2026.07.26
- Scope(대상): `bottlenote-product-api`, `bottlenote-mono` user 도메인, `bottlenote-test-support`
- Original Plan(원본 계획): `plan/complete/remove-v1-auth.md` (git 히스토리)

## Context(배경)

v1 login은 요청 본문의 `email`과 `socialType`만 받아 소셜 토큰을 검증하지 않고 JWT를 발급했고, 계정이 없으면 생성까지 했다. 이메일 문자열 하나로 임의 사용자 로그인이 가능한 공개 엔드포인트였다. `restoreUser()`도 BASIC일 때만 비밀번호를 검사해 소셜 계정은 이메일만으로 탈퇴 복구가 됐다. FE·앱 교차 조사 결과 v1 login을 실제로 쓰던 경로는 웹 카카오 로그인 하나였고, 작업 중 FE가 v2로 전환해 참조 클라이언트가 0이 됐다. 앱은 WebView 셸이라 FE 배포만으로 커버됐다.

## Decision(결정)

- `POST /api/v1/oauth/login`을 제거한다. 로그인 수단은 카카오·애플 v2 두 가지뿐이다. 애플은 id_token의 서명·issuer·audience·nonce를, 카카오는 백엔드가 카카오 API로 직접 검증한다.
- 이메일/비밀번호(BASIC) 로직 일체(`BasicLoginRequest`, `SocialType.BASIC`, `User.password`, `OauthService`)와 탈퇴 계정 복구 API를 제거한다.
- 토큰 재발급·검증은 v1 경로를 유지하고 v2에도 같은 엔드포인트를 복제한다. 로직은 `AuthService.reissue()/verifyToken()` 하나를 공유한다.
- admin-api의 관리자 로그인(`AdminAuthService`, `AdminUser.password`)은 별개 체계이므로 건드리지 않는다.
- `users.password` 컬럼은 남긴다. 엔티티 필드만 제거하며 `ddl-auto: validate`는 엔티티에 없는 컬럼을 문제 삼지 않는다. 컬럼 DROP은 후속 마이그레이션이다.
- 미사용 `SocialType.NAVER/GOOGLE/NONE`은 유지한다.

### Rejected Alternatives(선택하지 않은 대안)

- v1 login에 토큰 검증 추가: 같은 계약을 v2가 이미 제공하므로 중복이다.
- 재발급·검증까지 v2로 강제 이동: 취약점이 아니고 FE가 헤더 방식으로 `/api/v1/oauth/reissue`를 쓰고 있어 순수 비용이다.
- 계정 복구를 v2로 재설계: 필요가 확인되면 별도로 한다.

## Status(상태)

Accepted(승인됨)

- Implementation Record(적용 기록): 적용됨

## Consequences(결과와 영향)

- 카카오 access token의 발급 앱 검증(`KAKAO_APP_ID`)이 후속 커밋으로 이어졌다.
- 테스트 인증은 `TestAuthenticationSupport`가 `JwtTokenProvider`로 직접 발급한다.
- 교훈: 서브모듈이 있는 저장소에서 `git commit -am`은 포인터를 함께 옮긴다. 파일을 명시적으로 `add`한다.
