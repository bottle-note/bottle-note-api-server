# ADR: Product 목록은 HMAC keyset cursor, Admin 목록은 page/size로 계약을 분리한다

- 상태: 적용됨
- 결정일: 2026.08.15 (Admin 분리 2026.08.16, 타입명 정리 2026.08.22)
- 대상: `bottlenote-mono` global.pagination, `bottlenote-product-api`, `bottlenote-admin-api`
- 관련 이슈: `bottle-note/workspace#385`(계약 논의), `#402`, `#404`, `#407`
- 원본 계획: `plan/keyset-cursor-pagination.md`, `admin-product-pagination-separation.md`, `keyset-cursor-type-naming.md` (git 히스토리)

## 결정

- Product 목록 API(20개 + notifications)는 숫자 offset cursor를 버리고 HMAC-SHA256 서명 keyset cursor로 전환한다. 요청은 `cursor` + `size`, 응답은 `content`(또는 `items`) + `meta.pagination.hasNext/nextCursor`다. `totalCount`는 제공하지 않는다. 기존 라우트를 일괄 브레이킹했고 FE 전환은 workspace#394다.
- cursor는 정렬·필터 context와 마지막 item의 seek key를 담은 opaque 문자열이다. 서명 불일치는 `INVALID_CURSOR`(400), 다른 정렬·필터의 cursor 재사용은 `CURSOR_CONTEXT_MISMATCH`(400), 만료는 `CURSOR_EXPIRED`(410)다. 기존 배포 cursor 호환 의무는 없다.
- 정렬별 seek key는 결정적 tie-breaker로 ID를 포함한다. 예: 리뷰 탐색 `createAt + id`, 큐레이션 피드 `displayOrder + id`, 주류 탐색 RANDOM은 `CRC32(seed, id)`.
- 공통 타입은 `app.bottlenote.global.pagination`의 `KeysetPageRequest`, `KeysetPagination`, `KeysetPageResponse<T>`다. offset/page-number 타입과 구분되도록 이름에 `Keyset`을 넣었고, `CursorProperties`, `HmacCursorCodec`, `CursorClaims`, `CursorKeys`는 역할이 드러나므로 유지했다.
- Admin 목록 API는 `page` + `size`와 `GlobalResponse.fromPage`(meta.page/size/totalElements/totalPages)를 유지한다. #402에서 Product를 따라갔던 Admin help는 page/size로 원복했고, Admin 위스키 룩업은 `AdminAlcoholLookupService`로 분리했다.
- Admin 컨트롤러는 Product 목록 Service/Repository(커서 코덱·`KeysetPageResponse`를 끌어오는 경로)를 직접 쓰지 않는다. Product 페이징 타입을 바꿔도 Admin이 깨지면 안 된다. Admin yml에서 `PAGINATION_CURSOR_SECRET`을 제거했고 Product만 `CursorSecretValidator`로 secret을 필수로 한다.
- `/api/v1/alcohols/search`는 삭제했다.

## 배경

Product 목록이 숫자 offset을 cursor라 부르며 쓰고 있어 RANDOM 정렬·삽입 중 중복·누락이 생겼고, 클라이언트가 임의 offset을 만들 수 있었다. keyset으로 바꾸면서 Admin까지 같은 계약에 끌려갔는데, Admin은 총 건수·페이지 이동이 필요한 관리 화면이라 맞지 않았다. 계약 논의(#385)에서 Product는 cursor, Admin은 page/size로 갈라졌다.

## 선택하지 않은 대안

- Admin도 keyset cursor: 총 건수와 임의 페이지 이동을 잃는다.
- 서명 없는 keyset cursor: 클라이언트가 seek 값을 조작해 필터를 우회할 수 있다.
- `Pagination`/`PageResponse` 이름 유지: offset 타입과 구분되지 않아 혼동을 낳았다(#407).

## 결과와 비용

- access-control IP ban의 `max` 상한 목록과 `GET /v2/curation-specs` 전량 목록은 #404 변환 대상이 아니다.
- 새 정렬을 추가하면 seek predicate, orderBy, cursor keys, context를 함께 확장해야 한다. 큐레이션 정렬 선택(2026.08.21 ADR)과 검색 결과 집합 규칙(2026.09.05 ADR)이 그 예다.
- 레이어 표준 3에 따라 도메인 레포지토리 시그니처에는 Spring Data `Page/Pageable` 대신 이 타입을 쓴다.
