# ADR: 운영 인증값은 기본값 없이 기동 실패시키고 CORS는 프로파일별 allowlist로 한다

- 상태: 적용됨
- 결정일: 2026.07.18
- 대상: `bottlenote-product-api`, `bottlenote-admin-api`, `bottlenote-batch`
- 관련 PR: `bottle-note/bottle-note-api-server#662`
- 원본 계획: `plan/complete/bottlenote-security-hardening.md`, `batch-critical-hardening.md` (git 히스토리)

## 결정

- JWT secret, Admin root password, batch nonce salt 등 운영 인증값은 설정 파일에 하드코딩 기본값을 두지 않는다. 환경변수가 없으면 설정 바인딩 또는 기동이 실패해야 한다. 테스트·로컬 값은 테스트 또는 로컬 전용 설정에서 명시적으로 제공한다.
- refresh token 원문은 어떤 로그 레벨에서도 기록하지 않는다.
- CORS 허용 Origin은 비밀값이 아니므로 프로파일별 YAML로 관리한다. 운영 Product는 `https://bottle-note.com`, 운영 Admin은 `https://admin.bottle-note.com`만 허용하고, 개발은 각 development 도메인과 localhost 포트를 허용한다. 비허용 Origin에는 `Access-Control-Allow-Origin`을 반환하지 않는다.
- stateless JWT + `Authorization: Bearer`, CSRF 비활성화, `allowCredentials=false`는 유지한다.
- Admin Dashboard의 검색엔진 차단(`robots.txt`, `X-Robots-Tag`)은 대시보드 저장소가 담당하고, 사용자 서비스 프론트에는 적용하지 않는다.

## 배경

운영 설정에 JWT secret과 root password의 fallback 기본값이 있어 환경변수가 빠져도 기동됐고, refresh token이 로그에 남았으며, CORS가 전면 허용이었다. batch도 실행 JAR에 secret 기본값을 가지고 있었다.

## 선택하지 않은 대안

- Bucket4j + Redis rate limit: 이 PR 범위에서 제외했고 이후 access-control 도메인으로 별도 구현했다.
- CORS Origin을 SOPS secret으로 관리: 비밀값이 아니라 YAML로 충분하다.

## 결과와 비용

- 새 환경을 만들 때 필수 환경변수를 빠뜨리면 기동 시점에 바로 실패한다. 운영 사고 대신 배포 실패로 드러나는 것이 의도다.
- 문서 endpoint(OpenAPI JSON)는 일반 API와 분리된 문서 전용 CORS 정책을 쓴다(2026.08.03 ADR).
