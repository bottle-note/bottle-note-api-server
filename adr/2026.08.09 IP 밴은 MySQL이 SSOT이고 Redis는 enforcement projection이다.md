# ADR: IP 밴은 MySQL이 SSOT이고 Redis는 재생성 가능한 enforcement projection이다

- Decision Date(결정일): 2026.08.09
- Scope(대상): `bottlenote-mono` accesscontrol 도메인, `bottlenote-product-api`, `bottlenote-admin-api`, `git.environment-variables`(V9)
- Related PRs(관련 PR): `bottle-note/bottle-note-api-server#698`(access-control 도입 리뷰 수정)
- Original Plan(원본 계획): `plan/ip-ban-persistence.md`, `access-control-review-fixes.md` (git 히스토리)

## Context(배경)

밴이 Redis에만 있어 Redis 유실 시 복구할 수 없었고, 누가 언제 왜 밴했는지 감사할 수 없었으며, 공격/false positive 분석 근거가 남지 않았다. PR #698 리뷰에서는 Redis 장애가 API 가용성 장애로 전파되고(15초 점유), ban 목록 조회가 Redis 호출을 항목 수만큼 증폭하는 결함이 확인됐다.

## Decision(결정)

- `ip_bans`는 정규화 IP당 현재 상태 1행, `ip_ban_events`는 BAN/EXTEND/UNBAN/EXPIRE의 append-only 이력, `ip_security_signals`는 밴과 독립적으로 존재할 수 있는 탐지 근거(endpoint, method, rule code, 관찰 구간·횟수, Agent 식별자·버전, `UNKNOWN → CONFIRMED_ATTACK | FALSE_POSITIVE` 판정)다.
- 요청 경로의 필터는 Redis만 조회한다. 관리 명령은 DB 상태·감사 이벤트를 먼저 커밋한 뒤 최신 이벤트 ID를 버전으로 Redis에 반영한다. Redis 반영이 실패하면 DB 상태를 유지하고 관리 API는 `202 Accepted` + `PENDING_RECONCILE`을 반환한다. 성공으로 위장하지 않는다.
- Product의 JDBC Quartz 클러스터가 1분마다 단일 재조정 작업으로 DB의 활성·해제·만료 상태를 Redis에 수렴시킨다. 역순 이벤트는 무시하고, 비활성 상태는 `stateChangedAt/id` keyset으로 매분 최대 200건씩 순회하며 cursor를 JobDataMap에 지속한다. 만료된 ACTIVE는 SYSTEM EXPIRE 이벤트 후 versioned unban한다.
- 밴 기간은 1초~30일이며 영구 밴은 없다. 종료된 밴·이벤트·signal은 180일 보존 후 삭제한다.
- 자동 탐지·자동 밴은 범위 밖이다. Agent나 관리자가 밴 API에 선택적 signal 메타데이터를 전달한다. Agent 여부는 인증 Admin ID를 `agents.admin_user_id`로 매핑해 판별한다.
- 요청 본문, Authorization, Cookie, API key 등 비밀·민감 헤더는 signal에 저장하지 않는다.
- Redis 장애 시 access-control은 짧은 제한 시간(200ms) 안에 fail-open한다. 리뷰 GET과 쓰기 요청은 IP별 별도 rate limit 버킷을 쓴다. ban 목록 조회는 항목별 순차 Redis 호출 대신 DB에서 읽는다.
- 초기 seed는 저장소·운영 로그에서 침해 근거가 확인된 IP만 넣으며, 확인된 대상이 없어 V9의 초기 밴은 0건이다. 외부 위협 목록과 검색엔진 대역은 Flyway에 고정하지 않는다.

### Rejected Alternatives(선택하지 않은 대안)

- Redis를 SSOT로 두고 DB에 백업: 관리 명령의 원자성과 감사 이력을 보장할 수 없다.
- 관리 API가 Redis 실패를 200으로 반환: 운영자가 미반영 상태를 알 수 없다.
- 영구 밴 허용: 기존 정책(최대 30일)을 유지했다.

## Status(상태)

Accepted(승인됨)

- Implementation Record(적용 기록): 적용됨

## Consequences(결과와 영향)

- Admin API 응답에 `id`, `projectionStatus`가 추가됐고 기존 `ip/reason/ttlSeconds/banned`는 호환된다.
- 기존 행 명령은 `PESSIMISTIC_WRITE`로 직렬화하고 신규 insert 경합은 단발 재시도한다. 동일 IP 경쟁의 최종 방어선은 DB 제약이다.
- V9 마이그레이션은 Product/Admin 리소스에만 포함되고 Batch jar에는 들어가지 않는다.
