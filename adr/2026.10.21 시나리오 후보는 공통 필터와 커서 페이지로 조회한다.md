# 시나리오 후보는 공통 필터와 커서 페이지로 조회한다

- Decision Date(결정일): 2026.10.21
- Scope(대상): Product·Admin 속성 그룹 후보 API

## Context(배경)

관리 화면은 그룹에 연결된 위스키 목록을 받은 뒤 종류·도수·태그를 얻기 위해 각 위스키의 상세 API를 호출했다. 후보 약 600개를 대상으로 질문을 이어가는 제품에도 이 방식을 사용하면 최초 로딩 비용이 후보 수에 비례한다. 확장 속성에 기본 정보를 복제하면 원본과 추천 조건이 달라질 수 있다.

## Decision(결정)

`POST /api/v1/attribute/groups/{groupId}/candidates`와 `POST /admin/api/v1/attribute/groups/{groupId}/candidates`는 공통 서비스를 사용한다. 필수 그룹의 속성이 하나 이상 연결된 미삭제 술이 검색 범위다. 조건의 속성 ID도 해당 그룹 소속이어야 한다.

같은 숫자 속성의 상한·하한은 하나의 연결 값이 함께 만족해야 한다. `include`는 모두 만족해야 하고 `exclude`는 하나라도 만족하면 위스키 전체를 제외한다. 종류·도수·맛 그룹은 원본 데이터에서 판정하며 맛 그룹은 대표 태그 중 하나에 연결되면 일치한다. 도수는 숫자 또는 `%`가 붙은 숫자만 사용한다. 종류 목록과 맛 그룹 목록은 각각 OR이며 다른 조건과는 AND다. `NE`는 해당 속성 값이 존재하면서 같은 값은 전혀 없는 경우다.

후보는 ID 오름차순으로 정렬하고 `size` 기본 25, 최대 100의 HMAC 커서를 사용한다. Admin에서도 이 API는 추가 청크 로딩을 위해 커서를 사용하며 기존 offset 목록 계약은 변경하지 않는다. 커서는 그룹과 필터에 묶이고 `nextQuestion`과 페이지 크기에는 묶이지 않는다. 필터 변경 시 첫 페이지부터 조회한다. 데이터 변경을 고정하는 스냅샷은 제공하지 않는다.

응답 `data.items`에는 이름·이미지·종류·도수 원문과 숫자·숙성·캐스크·용량·지역·증류소·태그·일치하는 맛 그룹 코드·선택 그룹의 복수 속성 값을 담는다. 감사 주체·태그 아이콘·다른 그룹의 속성·개인화 정보는 포함하지 않는다. `data.totalCount`는 커서 이전 항목을 포함한 전체 교집합 수이며 `meta.pagination`에 `hasNext`와 `nextCursor`를 둔다.

선택적인 `nextQuestion`은 ATTRIBUTE, CATEGORY, ABV, TASTING_GROUP을 지원한다. ATTRIBUTE에만 `attributeId`를 지정한다. 숫자 속성 및 ABV에는 최대 20개 `ranges`를 지정하며 양끝은 포함된다. 각 범위는 `key`, `from`, `to`를 사용하고 한쪽 경계는 생략할 수 있다. 후보는 범위 안에 값이 여러 개 있어도 한 번만 센다. 숫자 최솟값·최댓값과 누락 후보 수도 반환한다. 문자열 선택지는 최대 100개와 `hasMoreOptions`를 반환하며, 그룹의 등록 값과 허용값에 있는 0개 선택지도 유지한다. 추가 페이지에는 `nextQuestion`을 생략하여 집계 비용을 줄일 수 있다.

후보 필터·페이지·전체 개수는 DB에서 계산하고 페이지 내 속성·태그는 일괄 조회한다. 선택지 집계에 필요한 ID와 값만 별도로 읽어 요청 안에서 계산한다. JVM 전역 후보 캐시는 추가하지 않는다.

## Status(상태)

Accepted(승인됨). API 경로, 페이지네이션, 공통 검색과 집계 제공에 대한 사용자 요청을 따른다. 승인 상태는 배포 완료를 뜻하지 않는다.

## Consequences(결과와 영향)

클라이언트의 개별 상세 호출을 제거하고 두 API가 같은 조건 해석을 사용한다. 페이지 크기를 늘려도 속성·태그 조회 횟수는 증가하지 않는다. 다음 질문의 집계는 현재 페이지가 아니라 전체 일치 후보를 읽으므로 후보가 크게 늘면 SQL 집계나 별도 최적화가 필요하다. 정렬은 추천 점수 순서가 아니며 후보 선별만 수행한다.

Admin 배포에는 `PAGINATION_CURSOR_SECRET` 설정이 필요하다. 공유 환경의 실제 키 설정은 이 변경에서 수행하지 않는다. 개발용 테스트 키는 테스트 설정에만 둔다. 시나리오 정의·공개 여부를 저장하는 기능은 별도이며 현재 API는 지정 그룹의 데이터를 조회한다.
