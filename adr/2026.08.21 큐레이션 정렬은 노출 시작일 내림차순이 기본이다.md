# ADR: 큐레이션 정렬은 `EXPOSURE_START_DATE DESC`가 기본이고 `DISPLAY_ORDER`는 명시 선택이다

- 상태: 적용됨
- 결정일: 2026.08.21
- 대상: `bottlenote-mono` curation 도메인, `bottlenote-product-api`, `bottlenote-admin-api`
- 관련 이슈·PR: `bottle-note/workspace#410`, `bottle-note/bottle-note-api-server#715`
- 원본 계획: `plan/curation-date-order-contract.md` (git 히스토리)

## 결정

- Admin 큐레이션 목록과 Product 큐레이션 feed는 `sortType={EXPOSURE_START_DATE, DISPLAY_ORDER}`, `sortOrder={ASC, DESC}`를 받는다. 누락 기본값은 `EXPOSURE_START_DATE + DESC`다.
- "큐레이션 날짜"는 `Curation.exposureStartDate`다. spec payload의 날짜는 정렬 SSoT가 아니다.
- `EXPOSURE_START_DATE`는 ASC/DESC 모두 null-last이며 DB 기본 null ordering에 의존하지 않고 명시적 null rank를 쓴다. 동일 날짜·null bucket은 요청 방향의 `id`로 결정한다. `DISPLAY_ORDER`는 요청 방향으로 정렬하고 동률은 같은 방향 `id`다.
- Product keyset cursor의 context에 `sortType`, `sortOrder`, 기존 filter context를 포함해 다른 정렬의 cursor 재사용을 거부한다. keys에는 정렬별 primary value와 `id`를 담고 날짜 정렬은 null bucket 전환을 처리한다.
- Product 일반 목록 `/api/v2/curations`의 기존 `displayOrder` 계약은 바꾸지 않는다. 대상은 Admin 목록과 feed다.
- visibility와 keyword/spec code 필터는 정렬 전에 그대로 적용한다. DB migration은 없다.

## 배경

live main은 Admin/Product 모두 `displayOrder ASC, id ASC` 고정이었다. 첫 구현(#715)은 이를 고정 `exposureStartDate DESC`로 바꿨으나, 사용자가 정렬 속성과 방향을 선택하는 request를 요구해 가정이 폐기됐다. 재승인된 계약은 같은 정렬 matrix를 Admin과 Product가 공유하되 수동 노출 순서를 명시적으로 고를 수 있게 하는 것이다.

## 선택하지 않은 대안

- 고정 날짜 정렬: 어드민이 손으로 맞춘 노출 순서를 쓸 수 없다.
- 정렬을 Product에서 별도 enum으로 정의: Admin·Product가 다른 값을 쓰면 확인 화면과 실제 노출이 어긋난다.

## 결과와 비용

- 진행 중이던 페이지는 재조회해야 한다. 기존 배포 cursor 호환 의무는 없다.
- QueryDSL seek helper는 날짜·숫자 path별로 typed로 분리했다(`ComparableExpressionBase`에 `gt/lt`가 없음).
