# ADR: 스펙 기반 큐레이션 v2는 별도 도메인과 서버 내부 GraphQL hydration으로 만든다

- Decision Date(결정일): 2026.05.15 (Product v2 노출 기간 필터 2026.05.17, Admin URL 정정 2026.05.18)
- Scope(대상): `bottlenote-mono` curation 도메인, `bottlenote-admin-api`, `bottlenote-product-api`, `git.environment-variables`
- Original Plan(원본 계획): `plan/complete/spec-based-curation-v2-graphql-sdl.md` (git 히스토리)

## Context(배경)

큐레이션이 키워드 → 주류 ID 목록 고정 구조라 화면별 레이아웃·항목 유형을 표현할 수 없었다. 스펙(JSON schema)으로 payload를 검증하고 서버가 주류 통계를 채워 넣는 구조가 데모에서 검증됐고, 이를 전체 기능(도메인, 스키마, Admin/Product endpoint, payload 검증, hydration)으로 한 번에 옮기기에는 범위가 커서 3 phase로 나눴다.

## Decision(결정)

- `curation_demo`에서 검증한 spec 기반 큐레이션을 기존 `CurationKeyword`를 개조하지 않고 별도 `app.bottlenote.curation` 도메인으로 이식한다. 기존 `curation_keyword`, `curation_keyword_alcohol_ids` 테이블과 기존 endpoint는 이식 기간 동안 유지한다.
- 저장 payload는 OpenAPI 스펙(`bottlenote-mono/src/main/resources/openapi/curation/*.json`)으로 검증하고, 응답은 response spec + GraphQL hydration으로 조립한다.
- GraphQL은 외부 공개 endpoint가 아니라 서버 내부 hydration 경계다. SDL은 `Query.alcohols(ids: [ID!]!)`와 `Alcohol` 표시·stats 필드만 노출하고, 사용자별 원본 목록(`picks`, `reviews`, `ratings`)은 노출하지 않는다. GraphQL/GraphiQL은 외부에서 차단한다.
- 없는 alcohol id는 결과에서 제외하고, 중복 id는 resolver에서 제거하며 반환 순서는 요청 순서를 따른다. `MANUAL` 항목(`alcoholId = null`)은 hydration 대상에서 제외한다.
- hydration 실패는 부분 성공으로 처리하지 않고 `CURATION_GRAPHQL_EXECUTION_FAILED`(500 계열)로 닫는다.
- 외부 계약은 Admin `/admin/api/v2/curation-specs`, `/admin/api/v2/spec-based-curations`, Product `/api/v2/curations`, `/api/v2/curations/{curationId}`다. Product v2는 `isActive`와 노출 시작·종료일로 필터하며 null 노출일은 열린 구간이다.
- 구현 클래스는 `GraphQL*` prefix로 통일한다.

### Rejected Alternatives(선택하지 않은 대안)

- 기존 `CurationKeyword` 확장: 키워드 기반 모델과 스펙 기반 모델의 수명주기가 달라 개조 대신 병존을 택했다.
- GraphQL을 외부 API로 공개: 인증·rate limit·보안 표면이 늘어나므로 내부 hydration에만 쓴다.
- 부분 성공 응답: 일부 항목만 채워진 큐레이션이 화면에 노출되면 오류를 감추게 되어 실패로 닫는다.

## Status(상태)

Accepted(승인됨)

- Implementation Record(적용 기록): 적용됨

## Consequences(결과와 영향)

- 큐레이션 응답 payload는 API 계약이다. `x-feed` 스펙 보정은 프론트와 협의해야 한다.
- 스펙 파일 버전(`3.0.x`)이 계약 버전이며, 스펙 변경마다 `Curation*SpecContractTest`를 갱신한다. 예: `PROGRAM.programs`를 선택 입력으로 바꾼 workspace#405(2026.08, 리소스 버전 3.0.3).
- 피드 Read Model 분리와 재생성 정책은 별도 ADR(2026.07.28)이 다룬다.
