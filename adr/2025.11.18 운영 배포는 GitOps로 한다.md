# ADR: 운영 배포는 개발 환경과 같은 GitOps(Argo CD) 방식으로 한다

- 상태: 적용됨
- 결정일: 2025.11.18
- 대상: `.github/workflows`, `git.environment-variables` (kustomize overlay)
- 원본 계획: `plan/complete/production-gitops-migration.md` (git 히스토리)

## 결정

- 운영도 개발과 동일하게 GitHub Actions가 이미지를 빌드·푸시하고 `environment-variables`의 kustomize 이미지 태그를 갱신하면 Argo CD가 감지해 배포한다. SSH로 서버에 접속해 Docker Compose를 실행하던 레거시 경로는 제거한다.
- 이미지 태그는 개발·운영 모두 short SHA(7자리)로 통일한다.
- 빌드 인자 `GIT_COMMIT`, `GIT_BRANCH`, `BUILD_TIME`을 이미지에 넣는다.
- Argo CD는 automated sync(prune, selfHeal)로 운영한다.
- ECR 토큰 갱신 CronJob의 네임스페이스 하드코딩을 제거한다.

## 배경

개발은 이미 Argo CD 기반이었지만 운영은 Oracle 서버 2대에 SSH 롤링 배포를 하고 있어 배포 방식이 이원화됐고, 운영 이미지의 빌드 인자 누락과 `development_latest` 잘못된 참조 같은 설정 오류가 있었다.

## 선택하지 않은 대안

- SSH 배포 유지: 배포 절차와 매니페스트가 두 벌이 되고 롤백이 수동이다.

## 결과와 비용

- k8s 매니페스트는 이 저장소가 아니라 별도 저장소에 있다. 로컬에서 이미지 빌드·푸시·매니페스트 수정을 직접 하지 않는다(`CLAUDE.md`).
- Oracle 레거시 환경 정리와 ECR retention 정책은 후속으로 남겼다.
- 이후 릴리즈 PR 경로와 서명 검증 후 승격 구조는 별도 ADR(2026.09.04)이 다룬다.
