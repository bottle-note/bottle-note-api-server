# ADR: Agent 인증은 `agents` 테이블이 Product/Admin 계정 FK와 API Key 해시를 소유한다

- Decision Date(결정일): 2026.08.01
- Scope(대상): `bottlenote-mono` agent/user/admin 도메인, `bottlenote-product-api`, `bottlenote-admin-api`, `git.environment-variables`
- Related Issues(관련 이슈): `bottle-note/workspace#340`
- Original Plan(원본 계획): `plan/agent-key-token-exchange.md` (git 히스토리)

## Context(배경)

이전 구현(V6)은 계정 테이블에 `agent_id`를 두는 역방향 FK였고, 다른 마이그레이션이 V6 번호를 선점해 Agent 마이그레이션을 V7로 교체해야 했다. 재작업하면서 FK 방향을 "에이전트가 자기 계정을 참조"로 바로잡았다.

## Decision(결정)

- `agents`가 `product_user_id`, `admin_user_id`로 기존 `users`, `admin_users`의 PK를 참조한다. 계정 테이블에는 ALTER 없이 전용 계정 6개(`bottlenote.agent.a~f@email.com`)만 INSERT한다. 역방향 FK(`users.agent_id`)와 역조회 계약은 제거한다.
- Agent 프로필과 API Key 메타데이터는 `agents` 단일 테이블에 두고 에이전트당 활성 키는 하나다.
- API Key 원문은 DB·SQL·코드·로그 어디에도 없다. V7 마이그레이션에는 SHA-256 해시만 기록하고, 원문은 서브모듈 루트 `agent/api-keys.sops.yaml`에 age로 암호화해 보관한다.
- Product/Admin 토큰 교환은 `Agent.productUserId`/`adminUserId` 기반 `findById`로 계정을 찾는다. 기존 JWT, refresh, 마지막 로그인, 오류·감사 계약은 바꾸지 않는다.

### Rejected Alternatives(선택하지 않은 대안)

- 계정 테이블에 agent 컬럼 유지: 사용자 도메인이 에이전트를 알게 되고 스키마 변경이 필요하다.
- API Key 테이블 분리: 에이전트당 키 하나이므로 단일 테이블로 충분하다.

## Status(상태)

Accepted(승인됨)

- Implementation Record(적용 기록): 적용됨

## Consequences(결과와 영향)

- 키 회전은 V-마이그레이션(해시 갱신)과 SOPS 파일 갱신을 함께 해야 한다.
- 통합 검증은 로컬 Docker 없이 PR CI에서 수행했다.
