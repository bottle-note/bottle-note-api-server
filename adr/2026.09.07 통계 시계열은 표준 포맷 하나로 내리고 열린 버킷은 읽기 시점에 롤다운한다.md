# ADR: 통계 시계열은 표준 포맷 하나로 내리고 열린 버킷은 읽기 시점에 롤다운한다

- 상태: 승인됨
- 결정일: 2026.09.07
- 대상: `bottlenote-admin-api`, `bottlenote-mono`, `bottlenote-test-support`
- 관련 문서: [인기도 관측은 시간·주·월 롤업 구조로 관리한다](<2026.08.23 인기도 관측은 시간·주·월 롤업 구조로 관리한다.md>)

## 결정

admin-api에 recharts용 시계열 통계 API를 추가한다. 모든 시계열 응답은 global 공유 커널의 표준 포맷 하나를 쓰고, 지표별 데이터 소유는 각 도메인에 둔다.

### 표준 시계열 포맷

`app.bottlenote.global.timeseries`에 두며 어떤 도메인도 참조하지 않는다.

```json
{
  "granularity": "DAY",
  "timezone": "Asia/Seoul",
  "from": "2026-08-09T00:00:00",
  "to": "2026-09-07T00:00:00",
  "series": [
    {"key": "visitors", "label": "방문자 DAU", "unit": "COUNT", "fill": "ZERO"}
  ],
  "points": [
    {"bucketAt": "2026-08-09T00:00:00", "partial": false, "values": {"visitors": 120}},
    {"bucketAt": "2026-09-07T00:00:00", "partial": true,  "values": {"visitors": 31}}
  ]
}
```

- 포인트 기준 구조다. 버킷 하나에 여러 시리즈 값을 싣고 시리즈 메타(`key`, `label`, `unit`, `fill`)는 따로 내린다. recharts `data`로 거의 그대로 쓴다.
- `granularity`는 `HOUR`, `DAY`, `WEEK`, `MONTH`다. 주는 월요일 시작, 시간대는 Asia/Seoul이다. API마다 지원 단위와 구간 상한을 선언하고 벗어나면 400이다.
- `bucketAt`, `from`, `to`는 ISO 로컬 일시 문자열(`yyyy-MM-dd'T'HH:mm:ss`)로 조립 단계에서 고정한다. 프로젝트의 `LocalDateTime` 커스텀 직렬화에 의존하지 않는다.
- 요청 구간의 모든 버킷을 빠짐없이 내린다. 빈 버킷은 시리즈별 `fill` 규칙으로 채운다. `ZERO`는 0, `NULL`은 null, `PREVIOUS`는 구간 안 직전 값이며 첫 값 전에는 null이다.
- `partial`은 버킷 종료 시각이 요청 시점보다 뒤인 포인트에 `true`다.
- `unit`은 `COUNT`, `PERCENT`, `SCORE`(0~1), `DECIMAL`이다.

### 방문자 통계 (`/v1/statistics/visitors/active`, `/retention`)

- `sp_view_dau` 프로시저를 호출하지 않는다. mono `statistics` 도메인의 JDBC 구현 레포지토리가 `visitor_telemetry_events`를 직접 집계한다. 프로시저는 DB에 남기되 코드에서 참조하지 않는다.
- 오전/오후 구분은 폐기하고 `DAY`, `WEEK`, `MONTH`만 지원한다. 구간 상한은 텔레메트리 보존 기간과 같은 90일이다.
- `active`는 고유 `visitor_id` 수와 고유 `user_id` 수다. 주·월은 같은 정의의 WAU·MAU다.
- 재방문율은 "해당 버킷 방문자 중 직전 버킷에도 방문한 비율"이다. 첫 버킷의 직전 버킷은 요청 구간 밖이라도 읽는다.
- 제외 규칙은 프로시저와 같다. `device_type` 제외 목록, IP prefix 제외 목록, `ip_address`가 NULL인 행을 뺀다. 여기에 `user_id`가 `root_admins`에 있는 행을 추가로 뺀다. 루트 관리자의 비로그인 행은 `user_id`가 없어 걸러지지 않으며 의도된 범위다.
- 제외 목록은 코드 상수나 DB 테이블이 아니라 `bottlenote.statistics.exclusion` 설정 프로퍼티다. 프로시저의 3옥텟 `IN`과 `LIKE` 두 방식을 prefix `NOT LIKE` 하나로 통일한다.
- 마지막 버킷은 요청 시점까지의 부분 집계이며 `partial: true`다.

### 주류 인기도 시계열 (`/v1/statistics/alcohols/{alcoholId}/popularity`, `/observations/{axis}`)

- admin-api에만 둔다. product-api 노출은 이번 결정 범위 밖이다.
- 저장 단위 `HOUR`, `WEEK`, `MONTH`를 그대로 쓴다. `DAY`는 HOUR에서 유도하지 않고 400으로 거절한다. 구간 상한은 HOUR 31일, WEEK·MONTH 366일이다.
- `popularity`는 `alcohol_popularity_snapshots`의 점수 5개(`SCORE`, `fill: NULL`)와 원시값 4개(`COUNT`)를 내린다. `observations/{axis}`는 축별 관측 테이블의 흐름값·상태값과 유도값(평균 평점)을 내린다. 흐름값은 `ZERO`, 상태값과 상태값에서 유도한 값(평균 평점)은 `PREVIOUS`다.
- 데이터 소유는 alcohols 도메인이다. 시계열 조립은 alcohols 서비스가 하고 `AlcoholPopularityFacade`로 공개한다. statistics 도메인은 alcohols의 레포지토리를 읽지 않는다. URL이 `/statistics` 아래인 것과 도메인 소유는 별개다.
- 배치는 닫힌 버킷만 만들므로 이번 주·이번 달 행이 없다. 요청 구간이 열린 주·월 버킷을 포함하면 그 버킷 하나만 요청 시점에 HOUR 행에서 롤다운해 `partial: true`로 붙인다. 닫힌 버킷은 항상 배치 행을 그대로 쓴다.
- 롤다운 규칙은 인기도 ADR의 롤업 규칙과 같다. 흐름값은 HOUR 합, 상태값은 기간 안 최신 HOUR 값이며 없으면 직전 닫힌 버킷 값을 이어받는다. 점수 5개는 전체 주류로 정규화해야 하므로 단일 주류로 계산할 수 없어 null로 둔다.

## 배경

- FE가 recharts로 방문자 DAU와 재방문율, 주류 상세의 인기도 추이를 그려야 한다.
- 기존 `sp_view_dau`는 Flyway 관리 밖의 DB 객체라 테스트 컨테이너에서 재현되지 않고, 날짜를 컬럼으로 피벗한 출력이라 시계열 API에 바로 쓸 수 없다. 봇·인프라 IP 대역도 프로시저 본문에 하드코딩되어 있어 대역이 바뀔 때마다 DB 객체를 고쳐야 했다.
- 인기도 데이터는 2026.08.23 ADR대로 배치가 시간·주·월 버킷을 미리 계산해 두며, 주·월은 기간이 닫힌 뒤(월요일 02:50, 매월 1일 03:50)에만 행이 생긴다. 이 구조를 그대로 읽으면 상세 화면에서 이번 주·이번 달 포인트가 비어 보인다.
- 지표마다 응답 모양이 다르면 FE 차트 컴포넌트를 지표별로 만들어야 한다.

## 선택하지 않은 대안

- 프로시저를 그대로 호출하거나 Flyway로 관리하며 호출: 피벗 출력 변환과 동적 SQL 유지 부담이 남고, `root_admins` 제외를 위해 프로시저를 고쳐야 한다.
- 오전/오후/전체 구간을 시리즈로 유지: 차트 시리즈가 6개로 늘고 주·월 단위와 맞지 않는다.
- 재방문율을 "직전 버킷 방문자 중 돌아온 비율"(유지율)이나 "최근 N일 이력 보유 비율"로 정의: 전자는 분모가 이전 버킷이라 시계열 포인트와 어긋나고, 후자는 파라미터가 하나 더 필요하다.
- 제외 목록을 코드 상수 또는 DB 테이블로 관리: 상수는 대역 변경마다 배포가 필요하고, 테이블은 스키마와 관리 API까지 범위가 커진다.
- 시리즈 기준 포맷(시리즈마다 포인트 배열): 시리즈별 범위가 다를 때 유리하지만 recharts에 넣으려면 FE가 버킷 기준으로 병합해야 한다.
- 주류 `DAY` 단위를 HOUR에서 읽기 시점에 유도: HOUR 보존 45일 안에서만 가능하고 점수는 하루 단위로 재계산할 수 없다.
- 열린 버킷의 점수에 최신 HOUR Snapshot 점수를 대입: 선은 이어지지만 시간 단위 정규화 값이라 주·월 점수와 척도가 다르다.
- 열린 버킷 롤다운 대신 응답 메타에 마지막 닫힌 버킷 시각만 표기: 상세 화면에서 이번 주 값을 볼 수 없다.
- statistics 도메인이 alcohols Facade에서 버킷 원본을 받아 직접 조립: statistics가 축별 필드 의미까지 알아야 해서 결합이 더 커진다.

## 결과와 비용

- 이후 지표(신규 가입, 리뷰 수 등)는 같은 포맷으로 추가하면 되고 FE 차트 컴포넌트를 재사용할 수 있다.
- 방문자 통계는 요청마다 원본 이벤트를 집계한다. 90일 일 단위 조회는 기존 `(occurred_at, visitor_id)`, `(occurred_at, user_id)` 인덱스 범위 스캔이며 현재 규모에서는 감당 가능하다고 판단했다. 실측은 하지 않았다.
- 재방문율의 첫 버킷은 직전 버킷 전체가 필요하므로 보존 기간 90일 경계에 걸리면 실제보다 낮게 나올 수 있다.
- 구간 상한(방문자 90일, 주류 HOUR 31일·WEEK/MONTH 366일)은 요청한 원본 날짜 기준으로 검증한다. 버킷 정렬로 `from`이 버킷 시작까지 내려가고 재방문율은 한 버킷을 더 앞서 읽으므로, MONTH 요청의 실제 조회 구간은 선언한 상한보다 최대 두 달 가까이 길어질 수 있다. 상한을 버킷 정렬 후 길이로 다시 검증하지 않기로 했다. 사용자가 고른 날짜가 그대로 400 여부를 정하는 편이 예측 가능하기 때문이다.
- `to`가 오늘보다 뒤인 요청은 400으로 거절한다. 미래 버킷은 값이 있을 수 없고 열린 버킷 판정을 흐린다.
- WEEK·MONTH 롤다운은 요청마다 주류 하나의 HOUR 행(최대 744행)을 읽는다. 캐시는 두지 않으며 필요해지면 Redis에 짧은 TTL로 둔다. 다중 인스턴스라 JVM 로컬 캐시는 쓰지 않는다.
- 열린 버킷의 점수가 null이라 점수 선은 마지막 닫힌 버킷에서 끊긴다. FE는 `partial`과 null을 구분해 표시해야 한다.
- 주류 HOUR 요청에서 `to`가 오늘이면 아직 오지 않은 시각의 버킷까지 `partial: true`로 내려간다(흐름값 0, 상태값 직전값). 미래 시각을 잘라내지 않고 포맷 계약(구간의 모든 버킷을 내린다)을 우선했다. FE는 `partial` 포인트를 그에 맞게 표시한다.
- 주·월 롤업 배치가 돌기 전(월요일 00:00~02:50, 매월 1일 00:00~03:50)에는 직전 닫힌 버킷의 행이 아직 없다. 롤다운은 열린 버킷 하나에만 적용하므로 그 시간대에는 직전 버킷이 `partial: false`인 채로 흐름값 0, 상태값 이어받기로 내려간다. 배치 완료 후 자연히 해소되는 일시적 공백이라 별도 처리하지 않는다.
- 빈 버킷의 `ZERO` 채움은 unit과 무관하게 정수 0이다. `PERCENT`·`DECIMAL` 시리즈에서 0과 0.0이 섞이지만 JSON 숫자로 동일하게 처리되므로 통일하지 않는다.
- `AlcoholPopularityFacade`가 global 타입 `TimeSeries`를 반환한다. 공유 커널 타입이라 레이어 표준 위반은 아니다. 클래스명을 `TimeSeriesResponse`로 두지 않은 이유는 ArchUnit DTO 규칙이 `*Response`를 `dto.response` 패키지에만 허용하기 때문이다.
