# 알림 저장은 JPA와 독립 트랜잭션으로 처리한다

## Context(배경)

알림과 수신 설정의 Native upsert는 JPA 감사 처리와 영속성 컨텍스트를 우회했다. 단순 JPA 저장으로 바꾸더라도 동일 키의 동시 INSERT가 발생할 수 있고, 실패한 트랜잭션 안에서 중복 예외를 잡으면 롤백 상태가 남는다. 사용자는 Native Query 사용을 금지하고 POC 알림 삭제와 구분 컬럼 제거를 승인했다.

## Decision(결정)

발생 액션 20종과 설정 그룹 5개, 전체 기본 ON, 기본값과 다른 설정만 저장하는 모델을 유지한다. 설정이 이미 있으면 다시 저장하지 않고, 기본값 복원은 JPQL 조건 삭제로 처리한다. 알림과 설정의 INSERT는 JPA로 실행하고 감사 정보는 기존 엔티티 리스너가 관리한다.

서비스가 TransactionTemplate으로 독립 트랜잭션을 소유한다. Repository에서 해당 테이블의 지정 UNIQUE 키 위반만 도메인 중복 예외로 변환하고, 서비스는 롤백 완료 후 그 예외만 멱등 처리한다. 다른 무결성 오류는 호출자에게 전달한다. 이 경계를 명확히 하기 위해 별도 저장 서비스나 커스텀 설정 Repository 구현체를 두지 않는다.

동시에 겹친 ON/OFF 요청은 클라이언트 전송 순서를 보장하지 않는다. 완료된 요청 뒤의 순차 요청은 최종 설정에 반영되어야 한다. 향후 그룹 설정 API의 원자성은 별도 구현 계약으로 정한다.

V18에서 POC 알림을 모두 삭제하고 type/category 컬럼을 제거한다. event_action은 필수이며, 표시 이름과 발생 설명은 enum에서 관리한다. CHECK·FK·추가 글자 수 제한은 도입하지 않는다. 기존 조회 필터·응답의 eventActions/groups 및 eventAction/group 계약을 유지한다.

## Consequences(결과와 영향)

설정 쓰기는 호출자의 트랜잭션과 별도로 완료된다. 실패한 INSERT의 rollback-only 상태가 호출자에게 전파되지 않으며, 조회 후 저장 사이의 경합은 DB UNIQUE 키가 방어한다. 알림 중복 전송은 최초 본문과 읽음 상태를 보존한다. SQL 오류 변환은 MySQL 중복 오류와 정확한 인덱스명을 확인하므로 스키마 인덱스명 변경 시 함께 수정해야 한다.
